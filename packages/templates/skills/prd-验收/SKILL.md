# PRD 验收

对 `product/PRD.md` 做分档验收。一次只推进一档；每档最多问 1～3 个问题。人答完立刻写回 PRD 对应章节，并更新 `product/gaps.md`（有则缩减，无则按需创建）。

## 开工前

1. Read `product/PRD.md`；若有则读 `product/gaps.md`、`product/import/original.md`。
2. 对照下方档位，找出**当前最低未过档**，只处理这一档。
3. 不要一次甩出整张问卷。

## 档位（按顺序）

### L0 骨架（不过不能往下走）

过关条件：

- 一句话目标不是占位、不是空话
- 背景与问题说清「谁 / 场景 / 痛点」
- 目标用户不是笼统「用户」
- 成功标准可观察
- 范围内、范围外都有实质内容
- ≥1 条完整用户故事（作为 / 我想要 / 以便 / ≥1 条可勾选验收）
- 入口与主流程有头有尾

缺口 → 写入 `gaps.md` 对应【背景与目标】【用户故事】【交互与体验】，并追问。

### L1 体验边角

过关条件：

- 关键界面写清这一期必须有的界面或状态
- 空态 / 失败 / 无权限时人看到什么有着落

仍写在 `## 交互与体验`。不必画高保真。

### L2 规格与约束（模板默认没有，需要时再开章）

若 PRD 尚无 `## 规格与约束`，先追加该章再填。按需追问（可声明「不涉及」并写明原因）：

1. 功能细则：规则、开关、默认值（和故事对得上）
2. 机型 / 系统 / 区域 / 品牌差异（无差异写「全机型一致」）
3. 权限与合规（不涉及就写「不涉及」）
4. 依赖：系统能力、其他 App、云端（不问选哪个代码仓）
5. 兼容 / 升级 / 回滚

一次只问其中 1～3 项未清的。

### L3 整包验收与发布

若尚无 `## 验收`，先追加该章。追问：

1. 整包验收清单（对照故事与主流程，可判定通过/不通过）
2. 指标 / 埋点（没有则写「本期不埋点」）
3. 发布门槛（谁签、哪些机型先上、出问题怎么关）

## 写回规则

- 已明确的立刻进 `PRD.md`，不要只留在对话里。
- `gaps.md` 每条指回章节；写清后勾掉或删掉，勿重复堆正文。
- 含糊词（「等」「看情况」「体验更好」）不过关，要追问成可判定表述。
- 不要编造导入原文没有的事实；对不上的留在 gaps「未能归入 PRD 的原文」。
- 代码能不能做、动几个仓 → 那是 `eng/方案.md`，本 skill 不管。

## 收尾

当前档过关时，用三行以内告诉对方：过了哪一档、下一档要补什么、是否建议继续。全部 L0–L3 过关且 gaps 无 P0 → 可提示把讨论重心转向共创 / 方案，而不是继续问卷。
