# 设计稿 2：信息架构与主路径

> 承接第 1 稿漏洞：首屏 10 秒、保存≠版本的界面位置、三种说话方式是档位不是三个产品。  
> 2026-08-16 修订：工作台仍三栏，但编辑台与 AI 任务互斥；工程列表要能看出「有人在用」。

---

## 结论

工作台**永远三栏**：左文件、中墨览、右 AI。对话不是首页，也不是引导阶段的主区。共创 / 拷问 / 可行性是右侧的三个档位，换档不换房子。

产品经理登录后 10 秒内只做一件事：打开一个已有工程。架构师多一排「建环境」入口，日常仍进同一套工作台。

顶栏永远能看见：工程名、当前文档、保存状态、「记入版本」、长任务是否还在跑、现在能不能改（编辑中 / AI 写文档中）。产品经理不看到本机绝对路径也可以；架构师可以展开看路径。

---

## 理由

第 1 稿把能力列全了，但旧 UX 讨论把「收集」做成主区问答、把架构/测试 Tab 灰着占位——那会让第一眼回到探针现在的样子：不知道下一步、聊天压过文档。已拍板的对话选型也说了：对话是纸面侧栏。所以本稿把 06 里「引导时主区是对话」视为过时，改成：

> 主区永远是文档纸面（墨览）。右侧永远是当前档位的 AI。左侧永远是这个工程的文档，不是某个代码仓的原样树。

代码仓对产品经理只以「只读、可调研」的身份出现在工程信息和信任条里，不进文件树。

---

## 页面地图

```text
登录
 ├── 架构师首页 ── 设置 / 用户 / 新建工程 / 打开工程
 └── 产品经理首页 ── 只：打开已有工程（含继续最近）
        │
        └── 工程工作台（三栏，本阶段唯一主界面）
              ├── 左：文档树 + 导入
              ├── 中：墨览（读 / 改 / 只读历史）
              └── 右：AI 档位（共创 | 拷问 | 可行性）
                    └── 本轮进度 / 取消 / 待记入的写入摘要
        附属（从顶栏或工作台打开，不是一级导航）
              ├── 版本时间线（抽屉或轻页）
              ├── 两版对比
              └── 离开前提醒（未保存 / 未记入版本）

以后才从工作台顶上露出、本阶段隐藏：
  技术方案 / SR / 测试方案
```

产品经理没有：设置、密钥、MCP、选文件夹、建用户、新建工程（第一版）。若架构师希望产品经理自己建工程，那是以后的权限开关，不是现在的首屏。

## 首屏

### 产品经理

```text
┌──────────────────────────────────────────┐
│  DesignWeave          李敏  ·  退出      │
├──────────────────────────────────────────┤
│  继续上次                                │
│  ┌────────────────────────────────────┐  │
│  │ 设置页夜间模式                      │  │
│  │ 上次：PRD.md · 2 小时前             │  │
│  │ 有一份进行中的可行性调研            │  │
│  │              [ 回到工程 ]           │  │
│  └────────────────────────────────────┘  │
│                                          │
│  全部工程                                │
│  · 设置页夜间模式                        │
│  · 负一屏天气卡片 · 李敏在编辑 · 可预览   │
└──────────────────────────────────────────┘
```

- 没有「新建」、没有「演示模式」、没有灰掉的架构/测试。
- 若某工程有进行中的长任务，卡片上直接说。**持有编辑权的人**点进去接上会话（墨览按人 XOR AI 可能只读）。别人点进去是**只读预览**，顶栏写「李敏正在编辑，你现在是预览」。
- 空状态（架构师还没建工程）：「还没有工程。请让架构师在这台工作台里创建一个，并给你账号。」不要放选文件夹。

### 架构师

同一布局，多一条工具条：

```text
│  [ 新建工程 ]   [ 用户 ]   [ 设置 ]         │
```

- **新建工程**：名称 → 选/建文档目录（托管机磁盘树）→ 声明「将作为文档版本库」→ 可选挂远端 → 勾选代码仓（可跳过，跳过则可行性不可用）。
- **用户**：创建产品经理账号，完成后给地址和登录方式（第一版口头/复制，不做邀请邮件视觉）。
- **设置**：Claude 是否已登录、MCP/skills 列表（可关）、监听地址。密钥不明文展示。产品经理打不开；直接访问管理接口则失败并说「需要架构师权限」。

架构师点某个工程，进入的工作台与产品经理**同一套**，只是顶栏多一个「工程设置」（改代码根、远端、再调研）。

## 工作台三栏

```text
┌──────────────┬─────────────────────────────┬─────────────────────┐
│ 设置页夜间模式│  PRD.md            已保存    │ 可行性 ▾            │
│              │  未记入版本 · [记入版本]     │  AI 只读：设置App,   │
│ 文档         │                             │  Framework · 未改代码│
│  ▸ PRD.md ●  │  # 设置页夜间模式            │                     │
│  ▸ 调研.md   │  …墨览正文…                 │  正在搜设置页里与    │
│  ▸ gaps.md   │                             │  夜间模式相关的实现  │
│  ▾ import/   │                             │                     │
│     original │                             │  [ 取消本轮 ]        │
│              │                             │                     │
│ [导入 md]    │                             │  说下一步…           │
└──────────────┴─────────────────────────────┴─────────────────────┘
  左 ~220        中（主）                       右 ~360
```

| 栏 | 职责 | 明确不做什么 |
|----|------|--------------|
| 左 | 只列文档仓。当前篇、未保存、AI 刚写下未看过，用圆点区分。导入入口在树底。 | 不列代码仓文件；不做通用笔记图谱 |
| 中 | 唯一纸面。人在编辑台时在这里改。AI 在写或打开历史版时整栏只读，顶上一条说明。 | 不在这里出工具 JSON、不在这里切架构 Tab；AI 进行中不准改字 |
| 右 | 当前档位的对话、进度、取消、本轮写了哪些文档。信任条钉在顶部。 | 不当整页 ChatGPT；不让产品经理选模型 |

默认比例大约 1 : 3 : 1.6。左栏和右栏都可收起；收起右栏时顶栏留一颗「AI」以免任务在跑却看不见。第一版不做独立窄屏布局，局域网用笔记本宽度即可。

> 2026-08-16 补：固定右栏已作废。人 XOR AI，谁在写谁占主——人改时纸面铺满，AI 收成底条；AI 跑时托付层浮在只读预览上。见 [13](./13-UI打磨计划.md)。

顶栏固定信息（两种角色都有）：工程名、当前文件名、「已保存 / 未保存」、「已是最新版本 / 未记入版本」、进行中任务红点。产品经理默认不显示绝对路径；点工程名可看「文档仓已连接、代码仓 N 个」而不暴露密钥。

## 三个档位怎么切换

右侧标题就是档位切换，三个互斥，**不新开页面**：

| 档位 | 人来干什么 | 右侧长什么样 | 墨览配合 |
|------|------------|--------------|----------|
| 共创 | 把想法说成 PRD | 每次 1～3 个问题（OEM 默认问：用户、机型范围、入口、权限、系统依赖、非目标、验收）。答完写入 PRD 对应节 | 打开 `PRD.md`，写到哪一节可把该节滚到眼前，但不抢焦点逼人看对话 |
| 拷问 | 查缺口、补逻辑 | 缺口列表为主，每条对应章节。人答一条，写回文档 | 点缺口时高亮对应标题；没有对应节就说「将新增一节」 |
| 可行性 | 对照代码问能不能做 | 进度用中文一句；可展开「查了什么」但不默认甩 JSON。结论写入 `调研.md` 和/或 PRD「可行性」节 | 进行中墨览**只读**，可打开已落下的 `调研.md` 并跟上；写完才恢复可改 |

未挂代码仓：可行性档位可见但锁定，文案：「这个工程还没有代码仓，无法对照实现调研。请让架构师挂上代码仓。」共创和拷问仍可用。

从共创切到可行性：不丢当前会话。每个档位有自己的会话列表（同一工程内），默认续最近一次；人也可以「新开一轮」。切换档位若当前轮还在跑，右侧提示「上一档还在写文档，可继续看或取消」。

一次只强调一个主行动：共创是「回答下一问」，拷问是「处理下一条缺口」，可行性是「让调研开始 / 看结论」，文档是「保存」或「记入版本」。不要同时闪三颗主按钮。人在改的时候不能开 AI；AI 在写的时候不能改——详见第 3 稿。

## 关键路径文字线框

### 路径 1：架构师最短配环境（含文档目录变成版本库）

```text
安装并启动 → 浏览器打开 → 创建第一个账号（架构师）
  → 设置页确认「已找到本机 Claude，MCP 已全部打开」
  → 用户：创建「李敏 / 产品经理」
  → 新建工程
        名称：设置页夜间模式
        文档目录：浏览托管机
           ├─ 空目录或新目录 → 默认勾选「初始化为文档版本库」
           └─ 已是版本库 → 使用它，并显示当前在主线
        远端：可跳过（P0 可只本机；栏位要在，免得到 P1 再找地方放）
        代码仓：从本机已有仓勾选 SettingsApp、Framework（可跳过）
  → 进入工作台（与产品经理同一套）
  → 把地址和李敏的账号交给人
```

失败人话举例：

- 「这台机器上还没有 Claude 登录。请在托管机完成 Claude 登录，或由架构师在设置里填写密钥。」
- 「选中的文档目录没有写入权限。」
- 「这个目录已经是版本库，但当前不在主线。第一版只支持主线，请换目录或先回到主线。」（实现细节见第 3 稿）

### 路径 2：产品经理主路径（打开 → 托付调研 → 人改 → 留下版本）

```text
登录 → 点「设置页夜间模式」（若李敏在编辑，自己以预览进入）
  → 三栏。中：上次的 PRD.md，可编辑。右：默认停在「共创」或上次档位
  → 切到「可行性」，输入托付
  → 若还有未记入的修改：先「保存一版并开始」
  → 墨览变只读。右侧：正在搜设置页夜间模式相关实现…
           信任条保持「只读代码仓 · 未改代码」
  → 左侧：出现 调研.md（或圆点表示正在写入）
  → 中：可点开 调研.md 只读看已落下的章节（即便右侧还在跑）
  → 想改字：提示「等 AI 写完，或取消本轮后再改」
  → 本轮结束：自动记一版（AI），墨览恢复可改，顶栏「可以改了」
  → 人改 PRD，Cmd+S → 「已保存，未记入版本」
  → 点「记入版本」，可改一句说明，确认
  → 之后可打开时间线：我的一版 / AI 的一版，对比或回到某一版
```

中途关浏览器：再打开同一工程，右侧自动接上那条可行性会话（先补已发生的说明，再接正在发生的）。取消只出现在右侧明确按钮，并先问一句：「取消后，已经写进文档的内容会留在纸面上；已记下的版本可以再回退。」

### 路径 3：导入后再追问

```text
左栏「导入 md」→ 粘贴或上传
  → 原文进 import/original.md，初版 PRD 尽量照原文，不自动重排
  → 右侧切到拷问，基于原文列缺口
  → 人要重排时，必须点「帮我规整章节」（P1 可先做成明确按钮，本阶段可灰但要留位）
```

### 路径 4：人与 AI 错开（取代「脏文档三选一」）

```text
人在编辑台 ──想开 AI──▶ 有未记入？
                         ├─ 是 → 「先保存一版」→ 保存一版并开始 → 墨览只读
                         └─ 否 → 轻确认后开始 → 墨览只读

AI 在做任务 ──想改字 / 导入 / 恢复──▶ 「等 AI 写完，或取消本轮后再改」

AI 写完 ──自动──▶ 可以改了；文件树和只读正文已经跟上
```

两人可以同时打开同一工程：一人编辑（或看自己的 AI 进度），其他人只读预览。细节见第 3 稿。

## 长任务在界面上的位置

- 进行中：右侧顶部状态 + 工程首页卡片 + 工作台顶栏红点。三处说的是同一件事。
- 离开再回来：进该工程即订回该会话。不要求产品经理记会话编号。
- 已部分落盘：只读墨览跟上即可。不要等整轮结束才允许打开（打开是看，不是改）。
- 失败：右侧停在人话原因，文档已写下的保留，并说明「没有改任何代码仓」。

## 信任如何被看见（本稿只放位置，文案钉在第 4 稿）

右侧顶上一行常驻，不随消息滚走。可行性进行中和结束后都在。时间线里 AI 的版本用「AI」而不是架构师的登录名，避免产品经理以为是同事改的。

## 本稿自批：3 个漏洞

1. **「记入版本」画在顶栏了，但何时自动记、AI 写完算不算一版，还在和开发猜谜。** 这是第 1 稿漏洞 2 的延续，必须第 3 稿一次拍死。
2. **预览和「AI 进行中的只读」长得像，但原因不同。** 顶栏必须写清：是「李敏在编辑，你是预览」，还是「AI 正在写，先不能改」。预览的人不能取消别人的 AI。
3. **历史版是「墨览整栏只读替换」还是「对照着看」没选。** 只读替换省事，但产品经理很难一边看旧版一边改新版；双栏对比又容易做成迷你 IDE。AI 进行中打开历史版可以，但不能「恢复到纸面」。
