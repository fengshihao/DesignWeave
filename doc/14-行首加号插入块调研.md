# 行首「+」插入块：社区实现调研

> 状态：调研记录 · 2026-08-18；同日改优先级并落地第一刀  
> 背景：墨览用 Vditor IR（类 Typora）。产品希望编辑时在行前出现「+」，点开后列出可插入元素（列表、代码、表格等）。  
> 相关：[05 编辑器选型](./05-Markdown编辑器选型调研.md)、[03 E2](./03-待确认问题.md)、[DEV.md](../apps/vscode-molan/DEV.md)

本文对照社区实现，并记下墨览的落地路径。落盘仍是 Markdown（见 [04](./04-文档存储原则.md)）。

## 1. 用户说的「每一行前边一个 +」实际长什么样

产品描述很像 Notion。社区落地后，**没有人在文档 DOM 里给每一行各插一个真实按钮**。

共同形态是：

```text
        ┌ 鼠标悬停这一块 ─────────────────────┐
  [+] [⠿]  这段文字……                            │
        └──────────────────────────────────────┘
           ↓ 点 +
        ┌ 插入 ──────────────────────────────┐
        │  标题  段落  引用  分割线           │
        │  无序 / 有序 / 任务列表             │
        │  代码块  表格  图片  公式           │
        └────────────────────────────────────┘
```

三件事绑在一起，缺一不可：

| 层 | 干什么 | 典型触发 |
|----|--------|----------|
| Handle | 行/块左侧出现控件 | 悬停（偶尔空块常显） |
| Menu | 列出可插入元素，可搜索、分组、键盘上下 | 点 `+`，或输入 `/` |
| Mutation | 改文档 | 空块：原地变成所选类型；有内容：在下方插一块 |

`+` 和 `/` **共用同一张菜单**。`+` 给不会 Markdown 的人；`/` 给键盘流。

「每一行」是**感知**，不是实现：鼠标移到哪一行，那一行左边出现同一个浮动控件。这样不污染选区、不进撤销栈、不写进 Markdown。

## 2. 社区怎么做（按引擎）

### 2.1 块模型编辑器（体验最好，md 多为导出）

内部文档是「块数组」，hover → 块 ID 是一等公民。`+` 几乎开箱即用。

#### BlockNote（Tiptap / ProseMirror）

- 文档：[Side Menu](https://www.blocknotejs.org/docs/react/components/side-menu)、[Suggestion Menus](https://www.blocknotejs.org/docs/react/components/suggestion-menus)
- 左侧 `SideMenu`：默认 `AddBlockButton`（+）+ `DragHandleButton`（⠿）
- `AddBlockButton` 的点击逻辑（源码要点）：
  1. 取当前悬停块
  2. 空块：光标放进去，`openSuggestionMenu("/")`
  3. 非空：`insertBlocks([{ type: "paragraph" }], block, "after")`，再打开同一 slash 菜单
- slash 菜单是 Suggestion Menu，触发符 `/`；选中项用 `insertOrUpdateBlockForSlashMenu`

这是「+ 就是程序化打开 `/`」的标准写法。

#### Milkdown Crepe · BlockEdit（MIT，md 一等公民）

- 文档：[Crepe API · BlockEdit](https://github.com/Milkdown/milkdown/blob/master/docs/api/crepe.md)
- 源码：`packages/crepe/src/feature/block-edit/`
  - `handle/`：`+` 与拖动手柄
  - `menu/`：slash 菜单（`SlashProvider`）
- 定位：`@milkdown/kit/plugin/block` 的 `BlockProvider` + [Floating UI](https://floating-ui.com/)
- hover 命中（`block-service.ts`）：
  1. `mousemove` 节流（约 200ms）
  2. 取编辑器水平中线 `x` + 鼠标 `y`
  3. `elementFromPoint` → 映射到 ProseMirror 根节点
  4. 过滤表格、引用、行内公式等不该出手柄的节点
- 点 `+`（`onAdd`）：
  1. 在当前块 **后面** 插入空 paragraph
  2. 把选区放到新段落
  3. `menuAPI.show(pos)` —— **不往文档里打 `/` 字符**
- 手输 `/` 时：`SlashProvider` 看当前段落是否以 `/` 开头、光标是否在节点末尾、是否在代码块/列表里；过滤词是 `/` 后面的文本
- 菜单分组（可配）：文本（段落/H1–H6/引用/分割线）、列表、高级（图/代码/表/公式）

Crepe 和墨览目标最接近：**Markdown 往返 + 现代块操作**。05 把它列为对照 POC，不是现在换引擎的理由。

#### Tiptap 官方 / 社区扩展

- 官方：[DragContextMenu](https://tiptap.dev/docs/ui-components/components/drag-context-menu)（`withSlashCommandTrigger` 在拖动手柄旁再放 slash 按钮）+ `SlashDropdownMenu`
- 社区：[`@tiptap-codeless/extension-drag-handle`](https://www.npmjs.com/package/@tiptap-codeless/extension-drag-handle) 把拖拽、空块插入按钮、`/` 菜单打成一个扩展；空块显示 `+`，有内容显示拖动手柄

#### Plate（Slate）/ Lexical

- Plate：`BlockDraggable` 画手柄；完整「+ 菜单 + 搜索」在 Plate Plus（商业）
- Lexical playground：实验性 `DraggableBlockPlugin`，偏拖拽，插入菜单要自建

### 2.2 在「非块模型」上叠一层（和墨览最像）

Vditor IR、Typora、Obsidian Live Preview **没有**「块 ID」。文档是字符流或 contenteditable DOM。社区做法是：**编辑器外面挂一个浮动手柄，用鼠标 Y 去猜当前行/块**。

#### Obsidian 插件 notion-block（[BCS1037/notion-block](https://github.com/BCS1037/notion-block)）

这是目前最完整的「给 Typora 类编辑器加 Notion 手柄」开源实现。Live Preview 底层是 **CodeMirror 6**。

源码拆分：

| 文件 | 职责 |
|------|------|
| `src/blockHandles.ts` | 唯一一个 handle 挂在 `scrollDOM` 上，随鼠标 Y 对齐逻辑行 |
| `src/notionInsertMenu.ts` | `+` 弹出的插入菜单（分组、键盘、子菜单） |
| `src/notionActionMenu.ts` | `⠿` 弹出的「变成标题/列表/代码…」 |
| `src/blockTransform.ts` | 往 CodeMirror 文档插 Markdown 字符串 |
| `src/dragDrop.ts` | 长按 150ms 才开始拖，避免和单击菜单抢手势 |

手柄定位要点（`blockHandles.ts`）：

1. **全编辑器共用一个** `.block-handle-wrap`，默认 `is-hidden`
2. `mousemove`：在 content 左缘取固定 `x`，`view.posAtCoords({ x, y })` → `lineAt(pos)`
3. 只有逻辑行号变了才 `updatePosition`
4. `coordsAtPos(line.from)` 得到行的屏幕矩形，再换算成相对 `scrollDOM` 的 `translate3d`
5. 左侧点击热区向左扩约 100px，避免手柄自己挡住命中
6. 离开后延迟隐藏（可配），避免移向 `+` 的路上按钮消失
7. 文档变更 / 视口滚动时，若手柄可见则重算坐标

点 `+`：打开插入菜单，**插入逻辑自己判断当前行空不空**（空则原地替换，非空则在下方新建一行再写入）。菜单是独立 DOM，不走 slash 字符。

#### Typora / 原版 Notion / Google Docs

- Typora：无行首 `+`；靠 Markdown 语法和顶栏。墨览现状更接近这条。
- Notion：块模型 + 悬停手柄 + slash，BlockNote/Crepe 在仿它。
- Docs：行首没有 `+`；插入靠菜单和 `/`。

### 2.3 Vditor 自己有什么（墨览现状）

墨览初始化见 `tools/markdown-viewer/molan-editor.js`：`mode: "ir"`，已有顶栏（标题、列表、代码、表格），`hint` 只设了 `delay: 400`，**没有** `hint.extend`，也没有行侧手柄。

Vditor 能用的挂钩：

| API | 能做什么 | 限制 |
|-----|----------|------|
| 顶栏 `list` / `code` / `table` / `headings` | 已有，光标处插入 | 新手找不到；不是行侧 `+` |
| `hint.extend`（`key: "/"`） | 输入 `/` 弹出补全 | 为 @/# 设计，不是块菜单 |
| `insertMD(md)` | 焦点处插入并走 Lute IR DOM | 要自己管光标和空行 |
| `insertValue` | 插 HTML 再渲染 | 代码块里的 HTML 易被二次解析（[#1640](https://github.com/Vanessa219/vditor/issues/1640) 才加了 `insertMD`） |
| `insertEmptyBlock(position)` | 插空块 | 仍要自己弹菜单 |
| `customWysiwygToolbar` | 只作用于 **wysiwyg** | IR 用不上 |

`hint` 源码（`src/ts/hint/index.ts`）关键行为：

- 看**当前文本节点、光标之前**的字符串，找 `extend.key` 最后一次出现
- 触发条件：key 在行首，**或** key 前面是空格；key 后最多 32 字符，且不能有前导空白
- 选中后：从 `lastIndex` 删到光标，再 `SpinVditorIRDOM(value)` 插回去
- 列表最多渲染 8 条；没有分组、没有程序化 `show()`
- 所以：`value` **不要以 `/` 开头**（否则删不干净）；`https://` 会误触，必须自己过滤「只在块首且前面不是 URL」

DEV.md / 03 E2 已写：slash 走 `hint.extend`。这对键盘成立，**撑不起行首 `+`**：没有「不往文档打 `/` 就打开 hint」的 API。

IR 的 DOM：`.vditor-ir .vditor-reset[contenteditable]` 里是 Lute 转出来的 `p` / `h1–h6` / `ul` / `pre` / `table` / `blockquote`。每次输入会 spin 重建局部 DOM。把按钮做进这些节点里，会被序列化进 Markdown 或被重建冲掉。

## 3. 实现模式对照

```text
模式 A  块模型内建          BlockNote / Crepe / Tiptap
        hover → node pos → SideMenu → 同一套 slash 命令
        换引擎或接受 JSON 内部模型

模式 B  编辑器外浮动层      Obsidian notion-block；Crepe 的 Floating UI 也是这个壳
        1 个 handle + mousemove 命中 + 自定义菜单 + 插 Markdown
        不改引擎

模式 C  只做 slash           Vditor hint.extend
        无行首 +；菜单简陋；已列入 E2

模式 D  每行一个真实按钮     CSS ::before / 每个块插 <button>
        社区不用。IME、选区、IR spin、getValue 都会踩坑
```

**不要做模式 D。** 即使用户口头说「每一行一个 +」，也做成模式 B 的「悬停跟随」。

## 4. 给墨览的建议

约束没变：Vditor IR、Markdown 落盘、浏览器工作室和 VS Code webview 同一套 `MolanEditor`（05 / 03 E1 已拍）。

### 4.1 已拍：先做行侧 `+`，slash 往后放

使用场景（2026-08-18）：文档多半是 **AI 写好的 Markdown**，人只修补；默认停在**预览**，用鼠标加点东西，不会手写语法。所以：

- **不做**第一刀 `hint.extend` `/`（键盘流，会写 Markdown 的人才用；之后再做）
- **先做**模式 B 的悬停 `+`，而且 **预览和编辑都要有**
- 预览里点菜单：直接改 Markdown 字符串并重绘预览（不必先点「编辑」）
- 编辑 IR 里点菜单：光标放到该块后，优先 `insertMD`

入口：`tools/markdown-viewer/molan-editor.js` 的 `bindBlockInsert`（工作室和 VS Code 扩展共用）。

```text
mousemove（节流）
  → 在纸面左缘固定 x + 鼠标 y 做 elementFromPoint
  → 命中当前顶层块（p / 标题 / 列表 / 代码 / 表 / 引用）
  → 用该元素 getBoundingClientRect 对齐唯一的 [+]
  → 离开延迟隐藏；手柄自身 mouseenter 取消隐藏

click [+]
  → 打开自绘菜单（分组：文本 / 列表 / 插入）
  → 预览：按块下标把 snippet 拼进 Markdown，renderLitePreview，标脏
  → 编辑：placeCaret + insertMD（没有该方法则退回拼字符串 + setValue）
```

手柄挂在 `.editor-wrap` 上，**不进** `contenteditable`，不会写进 `.md`。

**之后（slash）** 仍可用 `hint.extend`，或复用这一份菜单配置。不挡当前鼠标流。

**再之后（可选）** `⠿` 与拖拽。IR spin 更易打架，人修补场景也不优先。

### 4.2 明确不做

| 做法 | 原因 |
|------|------|
| 为 `+` 换成 BlockNote / 无头 Tiptap | 05 已否：内部 JSON，md 往返要单独验收 |
| 为 `+` 换成 Milkdown Crepe | 能得到完整 BlockEdit，但等于重做墨览 |
| 每个块节点插 `<button>` 或 `::before` 可点 | IR 重建、IME、选区、落盘 |
| 用 hint 冒充 `+` 菜单（先 `insertValue("/")` 再等 hint） | 闪一下 `/`、时序不稳、IME 易坏 |
| 把 slash 当作第一刀 | 预览修补场景里几乎没人会先打 `/` |

### 4.3 和现有能力的关系

顶栏已经能插列表 / 代码 / 表格；`+` 是给「看着预览、不想找工具栏、更不想写语法」的入口。菜单覆盖顶栏项，并补任务列表、Mermaid、公式、分割线。

只读跟随（人 XOR AI、别人预览锁）若以后接上，应隐藏手柄。当前工作室 / 扩展没有这层锁，预览可插。

### 4.4 风险

- **IME**：手柄 `pointerdown` 已 `preventDefault`
- **IR spin**：每次 hover 重新命中 DOM，不长期缓存节点
- **列表**：第一刀手柄对齐整块 `ul`/`ol`（不是每个 `li`），避免表格插进列表项
- **预览块下标 vs Markdown 块**：用同一套 GFM 切块；对不齐时仍插在命中下标后，极端文档可能错位
- **纸面左边距**：正文左 padding 收到 52px，给 `+` 留空
- **标脏**：预览插入也会走 `onInput`（原先预览态忽略输入，已改）
- **getValue 保真**：预览只改 Markdown 字符串；编辑走 `insertMD`，禁止手改 IR DOM 再指望 Lute 猜回来

## 5. 建议的菜单信息架构（产品侧）

中文优先，别名供 `/` 过滤（不必第一刀全做）：

| 分组 | 项 | 插入的 Markdown（示意） |
|------|----|-------------------------|
| 文本 | 正文 | 空段落 / 什么都不插 |
| | 标题 1–3 | `# ` / `## ` / `### ` |
| | 引用 | `> ` |
| | 分割线 | `\n---\n` |
| 列表 | 无序 / 有序 / 任务 | `- ` / `1. ` / `- [ ] ` |
| 插入 | 代码块 | 围栏 + 语言占位 |
| | 表格 | 两列 GFM 表 |
| | 公式块 | `$$` 围栏 |
| | Mermaid | ` ```mermaid ` 最小 flowchart |
| | 图片 / 链接 | `![]()` / `[]()` |

第一刀 slash 若受 8 条限制：标题、无序、任务、引用、代码、表格、Mermaid、公式。当前 `+` 菜单不受 8 条限制，上表可一次给齐。

## 6. 结论

1. 行首 `+` 在社区是 **悬停跟随的浮动手柄 + 插入菜单**，不是「DOM 里每行一个按钮」。
2. 块模型库把这件事做成引擎功能；Vditor IR 用 notion-block 那套外挂层即可。
3. **优先级已改：** 先 `+`（预览 + 编辑），`/` 后做。AI 写稿、人用鼠标修补，不会先去打斜杠。
4. 不换 Vditor。实现已落在 `molan-editor.js`；slash / 拖拽仍待做。
5. 验收：悬停出 `+`、点开能插列表/代码/表格、按钮不进 `.md`、预览插入会标脏、中文 IME 不被打断。
