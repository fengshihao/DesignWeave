# 数据层与业务层

> 状态：已拍板 · 2026-09-06 · 按此落地  
> 本文管：分层、工作台契约、用户增删改、统一鉴权、工程数据补全、业务接口、关键日志。  
> 工程目录 / PRD / 托付 / 文件夹锁 / 跟上仍听 [18](./18-工程目录与标准PRD.md)、[19](./19-对文档批注托付.md)、[20](./20-角色文件夹与变更跟上.md)。存储原则听 [04](./04-文档存储原则.md)。发送关卡听 [12](./12-实现前决策.md)。  
> 人若改口：先改本文和 [03](./03-待确认问题.md) 的 K 节，再动代码。  
> 本文**不**改墨览。UI 只当契约的视图。

当前实现的问题不是「没有接口」，而是**没有一层可离开 UI 单独测的业务**。路由里叠了校验、鉴权、落盘；前端 `api.ts`、agent 内部类型、`packages/schema` 各写各的；用户只能新建产品经理/测试，不能改角色、不能停用；工程字段残缺；几乎没有业务日志。

## 1. 分层

四层。依赖只许向下。业务层不准 import Express / Next / React。

```text
UI（apps/web）
  └── HTTP 适配（apps/agent/src/http）
        └── 业务（apps/agent/src/app）
              └── 数据（apps/agent/src/data）+ 契约（packages/schema）
```

| 层 | 放什么 | 不准放什么 |
|----|--------|------------|
| **契约** `packages/schema` | 实体、枚举、错误码、权限动作、zod。前后端共用。 | IO、Express、Better Auth 细节 |
| **数据** `apps/agent/src/data` | 磁盘 Markdown / Git、SQLite、Better Auth 仓储。输入输出是契约类型。 | 角色规则、发送关卡、「能不能建工程」 |
| **业务** `apps/agent/src/app` | 用例：`createUser`、`writeDoc`、`startRun`。先 `authorize`，再调数据层。返回结果或 `AppError`。 | `req` / `res`、Cookie、SSE 细节 |
| **HTTP** `apps/agent/src/http` | 登录态 → `Actor`，调用例，映射状态码，打请求日志。 | 拼路径、改 Markdown 表、算跟上 |

测试默认打**业务层**（临时目录 + 内存/文件 SQLite）。HTTP 契约测试第二刀。UI 测观感，不测「测试能不能建工程」。

`packages/schema` 里现有的 JSON PRD / Issue / SR / TechSpec **冻结**，移到 `packages/schema/src/legacy/`。工作台不再扩那套。新实体从本文起写在契约根上。

旧 HTTP `/v1/projects`（结构化 JSON 项目）和 `/v1/sessions`、`/v1/requirements/:id/chat`：**冻结，实现本层时删除**。工作台资源名统一为「工程」，路径用 `/v1/projects`。过渡期 `/v1/requirements` 可做同义别名，不长期并存两套语义。

## 2. 主体与存储

两类数据不要混。

| 类 | 真相源 | 丢掉会怎样 |
|----|--------|------------|
| **文档** | 运行根下工程文件夹（Markdown + 该文件夹 Git） | 不可接受 |
| **运行态** | SQLite | 工程列表可扫盘重建；锁 / run / 对话 / 审计会丢 |

### 2.1 用户（SQLite，Better Auth 表 + 业务字段）

一人一账号一角色。不做一人多角色。安装后第一个账号仍是架构师。

```text
User
  id            稳定 id
  name          显示名
  email         登录名，创建后不改
  role          architect | designer | tester
  status        active | disabled
  createdAt
  updatedAt
  createdBy     创建人 id；首账号为空
```

`status=disabled`：立刻注销其登录 session、放掉其持有的文件夹锁、不能再登录。已写的文档和历史 run **保留**，作者仍是这个 id。

**已拍板：**

- **一名架构师。** 只有安装后的第一个账号是架构师。不能再创建架构师，不能把别人升成架构师，也不能把架构师降级或停用。
- 架构师可以把产品经理 ↔ 测试互相改。
- 用户**停用不删除**。不做物理删号。停用后工程不改归属。
- 架构师可重置他人密码（一次性明文只在响应里出现，不写日志、不进审计详情）。
- 本人可改自己的姓名、密码；**不能**改自己的角色和 status。
- 创建账号只选产品经理或测试。密码至少 8 位。

### 2.2 环境（服务级，不是工程级）

```text
WorkspaceSettings
  workspaceRoot     运行根，绝对路径
  approvedCodeDirs  从 Claude 扫到的路径 ⊆ 批准名单
  systemPrompt      运行根 `.dw/system-prompt.md`（磁盘）
```

代码目录仍只从 `~/.claude.json` 扫入再批准，不浏览磁盘补挂。听 [01](./01-Claude配置复用与工程绑定.md)、[18](./18-工程目录与标准PRD.md) §6。

### 2.3 工程（磁盘为主，SQLite 只做缓存）

对外名称：**工程 / Project**。代码里不再用 Requirement 当主类型（旧函数可当别名，新契约不要出现）。

`meta.md` frontmatter 补全：

```text
id: abc12345
title: "设置页夜间模式"
ownerId: user_xxx          # 新建时写入；旧工程可空
ownerName: "阿朱"          # 展示冗余，以 User.name 为准
source: template | import
phase: filling | imported | clarifying | ready
clarity: pending | ready
createdAt: ...
updatedAt: ...
```

磁盘上还有：`product/` `eng/` `qa/` 固定文件（听 [20](./20-角色文件夹与变更跟上.md)）、`.git/`、`.dw/`。文件夹名 = 标题去掉非法字符；路由永远用 `id`。

SQLite `projects` 缓存（替换现在的 `requirements` 表）：

```text
id, title, owner_id, phase, clarity, vault_path, created_at, updated_at
```

丢掉这张表，扫运行根下带 `meta.md` 的子目录即可重建。`ownerId` / `phase` / `clarity` 以磁盘为准。

**本文补上、现状没有的工程用例：**

| 用例 | 规则 |
|------|------|
| 改标题 | 改 `meta.md`；文件夹重名则按 `名称-2` 改名；`id` 不变 |
| 改 owner | 仅架构师。只改 `ownerId` / `ownerName`，不搬文件夹 |
| 删工程 | 仅架构师。删子文件夹（含 `.git`）。同时清该工程的锁 / run / chat / 缓存 |
| 放弃 | 仅架构师。只丢缓存，不删盘。给运行根外的孤儿用 |
| 列表 | 全员可见运行根下全部工程。孤儿只给架构师 |

`phase` / `clarity`：**不再拦发送**（[19](./19-对文档批注托付.md) I4）。仍可读写，给列表标签用。谁能改：本工程产品文件夹的写者，或架构师。

文档正文不当结构化 JSON。PRD 五章、用户故事、`gaps.md` 指回章节、问题表四列，仍是 **Markdown 约定 + 模板**。业务层提供读写整篇、追加问题行、追加跟上条；不在第一刀做「解析 PRD 为对象再校验」。那是后一刀，单独开。

### 2.4 运行态（仅 SQLite）

| 实体 | 键 | 说明 |
|------|----|------|
| `FolderLock` | `(projectId, folder)` | 一夹一写者；心跳 2 分钟过期；`clientId` 区分同人两台设备 |
| `ChatSession` | `id` | 每人每工程私有；关面板 = closed，事件保留 |
| `WorkbenchRun` | `id` | 一轮托付；挂 `sessionId`、`folder`、`mode`、`focus` |
| `RunEvent` | `(runId, seq)` | AG-UI 子集，可重放 |
| `AuditEvent` | `id` | 见 §5。丢掉库则审计丢，可接受 |

锁、run、chat 的产品规则不改口，听 [20](./20-角色文件夹与变更跟上.md)、[07](./07-客户端架构.md) §3.2、[12](./12-实现前决策.md)。

## 3. 权限

不上 Casbin / OpenFGA。一张矩阵 + 一个函数：

```text
authorize(actor, action, resource) → ok | AppError(forbidden)
```

`Actor` = `{ id, name, email, role }`，由 HTTP 从登录 session 填。业务层只认 Actor，不认 Cookie。

`action` 是契约枚举，不要在路由里写死中文判断。资源不够时用 `resource.folder` / `resource.userId` / `resource.projectId`。

### 3.1 矩阵

| 动作 | 架构师 | 产品经理 | 测试 | 额外条件 |
|------|--------|----------|------|----------|
| `workspace.read` | 是（含路径） | 只看是否已设 | 只看是否已设 | |
| `workspace.write` | 是 | 否 | 否 | 运行根、批准名单、系统提示词、Claude 配置、浏览托管机目录 |
| `user.list` / `user.create` / `user.update` / `user.disable` / `user.resetPassword` | 是 | 否 | 否 | 不能创建/升降架构师；不能停用架构师；不能改自己的 role/status |
| `user.self.update` / `user.self.password` | 是 | 是 | 是 | 只改本人 name / password |
| `project.create` | 是 | 是 | 否 | 运行根必须已设 |
| `project.delete` / `project.abandon` / `project.transfer` | 是 | 否 | 否 | |
| `project.rename` | 是 | 是（仅自己建的，或 owner=自己） | 否 | **K3**：是否限 owner，见 03 |
| `project.read` | 是 | 是 | 是 | 运行根下全员可见 |
| `doc.read` | 是 | 是 | 是 | 工程内全部 Markdown |
| `doc.write` | `eng/` | `product/` | `qa/` | 还要持有该文件夹锁；`If-Match` |
| `doc.question.append` | 是 | 是 | 是 | 可写别人文件夹的 `问题.md` 一行，不抢锁 |
| `version.record` / `version.restore` / `version.revertAi` | 本夹 | 本夹 | 本夹 | 持锁；记版只 stage 本夹（跟上条除外） |
| `lock.claim` / `heartbeat` / `release` | 本夹 | 本夹 | 本夹 | 无权写的夹：预览，不抢锁 |
| `lock.forceRelease` | 是 | 否 | 否 | 任一夹 |
| `run.start` | 本夹 | 本夹 | 本夹 | 持锁、未在编辑、本夹 git 干净；`ask` 要圈选、不占对方锁 |
| `run.cancel` / `run.read` | 本人的 run | 本人的 run | 本人的 run | `ask` 本人可取消；其它要持该夹锁 |
| `chat.read` / `chat.write` | 本人 | 本人 | 本人 | 不互看。架构师也**不能**在产品里看别人的对话 |

`meta.md`、`.dw/`、`product/import/` 不进侧栏，人不能当正文改。`product/gaps.md` 只产品经理侧 AI 维护，人手编辑算逃生口（听 [19](./19-对文档批注托付.md) I5），权限仍按 `product/`。

发送关卡（`run.start` 非 ask）仍是：持锁、该夹不在 editing、该夹干净、该夹没有进行中的一轮。清晰度和代码目录**不**拦发送。

### 3.2 错误

业务层抛 `AppError`，不要抛裸 `Error`。

| code | HTTP | 何时 |
|------|------|------|
| `unauthenticated` | 401 | 未登录 |
| `forbidden` | 403 | 角色不够、越权写夹、看别人的 chat |
| `not_found` | 404 | 工程/文件/用户不存在 |
| `conflict` | 409 | etag 不符、锁被占、夹脏、已有进行中 run、工程文件夹重名 |
| `invalid` | 400 | 缺字段、角色非法、最后一名架构师 |
| `not_ready` | 400 | 运行根未设还要建工程 |

HTTP 只做 `statusOf(err)`。文案用中文，写在业务层，UI 原样展示。

## 4. 业务接口

下列是**用例**，不是「有一条路由就算有设计」。每个用例：输入契约 → `authorize` → 数据层 → 审计（若需要）→ 输出契约。

### 4.1 账号

| 用例 | 输入 | 输出 | 谁 |
|------|------|------|----|
| `setupFirstUser` | name, email, password | User + 登录 cookie | 仅用户数为 0 |
| `signIn` / `signOut` | email+password / — | cookie | 任何人 |
| `getMe` | — | User | 登录者 |
| `updateMe` | name? | User | 本人 |
| `changeMyPassword` | current, next | ok | 本人 |
| `listUsers` | — | User[]（含 status） | 架构师 |
| `createUser` | name, email, password, role（designer \| tester） | User（响应里带一次 password，仅此一次） | 架构师 |
| `updateUser` | id, name?, role? | User | 架构师 |
| `disableUser` / `enableUser` | id | User | 架构师 |
| `resetUserPassword` | id, password | 一次性 password | 架构师 |

对应 HTTP（落地时按此挂，不再把 Better Auth 管理接口直接暴露给前端）：

```text
POST /v1/setup
POST /v1/login
POST /v1/logout
GET  /v1/me
PATCH /v1/me
POST /v1/me/password
GET  /v1/users
POST /v1/users
PATCH /v1/users/:id
POST /v1/users/:id/disable
POST /v1/users/:id/enable
POST /v1/users/:id/reset-password
```

不做：自助注册（首账号之后）、邮箱改绑、邀请链接、OAuth、模拟登录（impersonate）。

### 4.2 环境

```text
GET  /v1/workspace
PUT  /v1/workspace                      { workspaceRoot }
GET  /v1/workspace/system-prompt
PUT  /v1/workspace/system-prompt        { text }
POST /v1/workspace/system-prompt/reset
GET  /v1/workspace/code-dirs
PUT  /v1/workspace/code-dirs            { approved: string[] }
GET  /v1/fs/browse
POST /v1/fs/mkdir
GET  /v1/claude/config
GET  /v1/claude/projects
```

规则不变。全部 `workspace.write`，除 `GET /v1/workspace` 对非架构师只回布尔。

### 4.3 工程与文档

```text
GET    /v1/projects
POST   /v1/projects                     { title, source, importMarkdown? }
GET    /v1/projects/:id
PATCH  /v1/projects/:id                 { title?, ownerId?, phase?, clarity? }
DELETE /v1/projects/:id
POST   /v1/projects/:id/abandon
GET    /v1/projects/:id/tree
GET    /v1/projects/:id/files?path=
PUT    /v1/projects/:id/files?path=     If-Match, { content, clientId }
POST   /v1/projects/:id/import          { markdown, clientId }
GET    /v1/projects/:id/versions?folder=
POST   /v1/projects/:id/versions        { folder, message?, markCaughtUp?, clientId }
GET    /v1/projects/:id/versions/:sha/files?path=
POST   /v1/projects/:id/versions/:sha/restore
POST   /v1/projects/:id/versions/revert-latest-ai
POST   /v1/projects/:id/questions       { folder, file, headingPath, question }
```

`PUT .../prd` 删掉，统一走 `files?path=product/PRD.md`。

### 4.4 锁、对话、托付

```text
GET  /v1/projects/:id/lock?folder=&clientId=
POST /v1/projects/:id/lock/claim|heartbeat|release
POST /v1/projects/:id/lock/force-release

GET  /v1/projects/:id/chat-sessions
POST /v1/projects/:id/chat-sessions
GET  /v1/projects/:id/chat-sessions/open
GET  /v1/projects/:id/chat-sessions/:sid
POST /v1/projects/:id/chat-sessions/:sid/close

POST /v1/projects/:id/runs              { message, clientId, sessionId?, focus?, folder? }
GET  /v1/projects/:id/runs
GET  /v1/projects/:id/runs/current
GET  /v1/projects/:id/runs/:runId/events
GET  /v1/projects/:id/runs/:runId/stream
POST /v1/projects/:id/runs/:runId/cancel
```

`mode` 请求里仍可收，执行一律当托付（现状已如此）。不要把四档 AI 做回来。

## 5. 关键日志

现在几乎只有进程启动的 `console.log`。落地后两类日志，都是 **一行一条 JSON**，打到 stdout；审计另外落 SQLite。

### 5.1 请求日志（每条 HTTP）

```text
ts, requestId, method, path, status, ms, userId, role, code?
```

不记 body、不记 Cookie、不记文件正文。`requestId` 由 HTTP 层生成，业务/审计带上。

### 5.2 审计（变安全边界或变真相源的动作）

表 `audit_events`：

```text
id, ts, requestId, actorId, actorName, actorRole,
action, projectId?, folder?, targetId?,
result: ok | deny | error,
detail  短 JSON，禁止密码/正文/token
```

**必须记：**

| action | 何时 |
|--------|------|
| `auth.login` / `auth.login_fail` / `auth.logout` / `auth.setup` | 登录成败 |
| `user.create` / `user.update` / `user.disable` / `user.enable` / `user.reset_password` | 管账号 |
| `workspace.set_root` / `workspace.set_code_dirs` / `workspace.set_prompt` / `workspace.reset_prompt` | 改环境 |
| `project.create` / `project.rename` / `project.transfer` / `project.delete` / `project.abandon` | 工程生命周期 |
| `doc.write` | 人保存一篇（path，不含正文） |
| `version.record` / `version.restore` / `version.revert_ai` | 记版、恢复、撤 AI |
| `lock.force_release` | 架构师强解 |
| `run.start` / `run.cancel` / `run.fail` | 托付起止（成功也可记，detail 只 mode/folder） |
| `authz.deny` | `authorize` 失败 |

**不记：** 读文件、列目录、心跳、SSE 每个 token、聊天全文。对话内容已在 `run_events`；审计不复制。

架构师可 `GET /v1/audit?limit=` 看最近审计。这不是「看别人聊天」。产品经理/测试 403。

## 6. 和现状的差（实现时按此补，不要另开口径）

| 缺口 | 现在 | 本文 |
|------|------|------|

| 日志 | 启动打印 | 请求日志 + 审计表 |
| 测试 | 辅助函数单测 | 业务用例先测，不经过 UI |

## 7. 明确不做（本层）

- Casbin / 组织 / 多租户 / OAuth / 邀请邮件
- 一人多角色、第四种角色
- 工程级成员名单（全员可见已拍板，不做成私有工程）
- 把 PRD / 方案 / 测试解析成 JSON 当主存储
- 实时协同、文档分支、远端 push
- 审计进产品当「动态时间线」；架构师偷看他人 chat
- 在业务层打 UI 文案拼装以外的 HTML
- 一边设计一边改墨览

## 8. 实现顺序（审过本文再开）

横切：每刀先契约 → 数据 → 业务 → HTTP → **该刀的业务测试**。UI 另挂，可晚一刀。

1. **骨架**：目录 `schema` / `data` / `app` / `http`；`AppError`；请求日志中间件；把现有路由挪到 http，行为先不改。  
2. **用户**：补 `status` / `createdBy`；§4.1 全部用例 + 测试（最后一名架构师、停用踢 session）。  
3. **工程契约**：`Project` 替换 Requirement；`meta.md` 补 `ownerId`；改名 / 转交；删旧 `/v1/projects` JSON 与 requirement chat。  
4. **authorize**：把写文件、建工程、锁、run 关卡收进矩阵；补越权测试。  
5. **审计**：表 + 必记动作；`GET /v1/audit`。  
6. **HTTP 正名**：`/v1/projects` 为唯一前缀；前端改调用。  
7. UI：用户管理补改角色/停用/重置；工程改名。不阻塞 1–6 的测试。
