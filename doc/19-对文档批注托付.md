## 1. 背景与目标

### 问题

上一版把用法规定死了：标准 PRD 五章、清晰度门闩、四档（检查清晰度 / 共创 / 拷问 / 可行性）。系统提示词写在代码里，用户不能调。早期用户无法把产品调成自己的工作方式。

同时，产品 / 设计 / 测试写文档的真实过程，本来就是**人和 AI 对着同一篇文档讨论、改、再讨论**——和 Claude Code 对着代码仓一样。不该先逼人进编辑器手改，再另开一档「托付」。

### 一句话

**圈住纸面上的一块，说一句，AI 改回去。** 只有一个输入，没有档位。架构师能改一条系统提示词。

### 目标

- 产品经理不用学 Cursor / Claude Code 的 `@`、模式、快捷键。
- 批注三步：圈 → 写 → 回车。没有第四步。
- 架构师能改系统提示词，下一轮生效。
- 硬规则（只写文档仓、不改代码）仍在代码里，人改不了。

### 成功标准（可观察）

1. 预览态圈一段字（或点一个标题），底条出现引文芯片，输入框聚焦。
2. 回车后 AI 改的是圈住的那一块（或其所在节），纸面刷新。
3. 全程没有选档位、没有 `@` 文件、不必进编辑。
4. 架构师在设置里改系统提示词并保存，下一轮托付用新文本。
5. 产品经理设置里看不到系统提示词。

### 非目标（本阶段不做）

- Playbook / 档位编辑器 / 检查表编辑器 / 模板市场
- Skill、subagent（可行性读代码、测试方案以后用这条做）
- 文档内嵌批注气泡、批注落盘、多选
- 逐段采纳 / 拒绝（否决仍用「撤销这一版」，听 [12](./12-实现前决策.md)）
- 改业务代码、公网 SaaS、重做墨览内核

## 2. 用户故事

### US-001 圈一块就问

- 作为：产品经理
- 我想要：在预览里圈住一段，直接问 AI 改这里
- 以便：不必进编辑，也不必描述「请改第三章第二段」
- 验收：
  - [ ] 预览态拖选非空文本后，底条出现引文芯片（含章节路径 + 摘录）
  - [ ] 输入框自动聚焦；回车发出本轮，body 带上焦点
  - [ ] 点芯片 × 或取消选区后，芯片消失，变回对整篇说

### US-002 点标题选整节

- 作为：产品经理
- 我想要：点「用户故事」这类标题，整节成为焦点
- 以便：不用精确拖很长一段
- 验收：
  - [ ] 点击 `h1`–`h6`，该标题到下一同级（或更高级）标题之前的正文成为焦点
  - [ ] 芯片展示章节路径，例如 `用户故事 / US-001`

### US-003 对整篇说一句

- 作为：产品经理
- 我想要：什么都不圈也能托付（起稿、导入后「帮我理一理」）
- 以便：空白纸或整篇重写仍走同一输入
- 验收：
  - [ ] 无选区时底条无芯片，发出的焦点 `quote` 为空、`file` 为当前打开的文件

### US-004 改系统提示词

- 作为：架构师
- 我想要：在设置里编辑一条系统提示词
- 以便：早期把 AI 调成自己团队的写法
- 验收：
  - [ ] 设置浮层有「系统提示词」：多行文本、保存、恢复默认
  - [ ] 存盘位置：`<workspaceRoot>/.dw/system-prompt.md`
  - [ ] 未设运行根目录时，保存给出人话错误，不写到别处
  - [ ] 产品经理打不开这项
  - [ ] 下一轮 `appendSystemPrompt` = 硬规则 + 该文件正文

### US-005 人手改仍能用（逃生口）

- 作为：产品经理
- 我想要：偶尔自己改错字或粘贴一大段
- 以便：不等一轮 AI
- 验收：
  - [ ] 墨览顶栏仍可进编辑、保存（现有行为）
  - [ ] 产品不把「先手改再托付」当主路径；默认仍是预览

## 3. 交互与体验

主区永远是墨览。对话是托付底条。听 [18](./18-工程目录与标准PRD.md) §7 的空间，**但去掉档位 Tab**。

```text
同一壳 · 全视口
┌ rail ─┬ 墨览纸面（默认预览）─────────────────────────────┐
│        │  圈选高亮 / 点标题高亮                              │
│        └──────── 底条：〔引文芯片〕〔输入〕〔发送〕 ─────────┘
└ 设置（架构师）：系统提示词 ─────────────────────────────────┘
```

### 简单到什么程度

只允许三步：圈 → 写 → 回车。

| 不要 | 用什么代替 |
|------|------------|
| 清晰度 / 共创 / 拷问 / 可行性 Tab | 那句话就是意图 |
| `@` 文件 | 服务端带当前文件 + 文档仓清单，模型自己 Read |
| Cmd+K 和 Chat 两套盒子 | **只有底条一个输入** |
| 改写 / 缩短 / 翻译一排按钮 | 用户自己写那句 |
| 快捷键教程 | 松手即出芯片，不必记键 |

选中之后不要再弹出第二个评论框。芯片长在现有底条左边。这是有意比 Cursor 少一套 Composer。

### 选区视觉

- 宣纸 / 墨夜纸面上用轻高亮，不要 IDE 蓝块。
- 芯片文案短：`章节路径 · 「摘录前 24 字…」`，全文不占底条。
- AI 进行中：纸面只读（现有锁），高亮保留，表示正在改这块。
- 写回后刷新纸面。不在 Markdown 里写入批注标记。

### 对话回显

每一轮用户消息上方一枚只读引文芯片（与底条同内容）。没有选区则不显示。线程只在托付层，不写进 `PRD.md`。

## 4. 规格：两层提示词

发给模型的 `appendSystemPrompt` 只有两层（再加本轮 user turn）：

```text
[硬规则 · 代码 · 人改不了]
[系统提示词 · <workspaceRoot>/.dw/system-prompt.md · 架构师可改]
```

动态的路径、目录卡、选区、用户原话走 **user turn**，不要写进系统提示词文件。

### 4.1 硬规则（代码常量）

必须包含：

- 只写文档仓 Markdown；禁止修改代码目录里任何文件。
- 代码目录若出现在 `additionalDirectories` 里，只许 Read / Glob / Grep。
- 先 Read 再改；不要输出「请把下面粘贴到文件」。
- 始终简体中文。
- 对方给了选区：优先改该引文所在位置；引文找不到时先问，不要乱改别处。
- 没有选区：按对方的话处理当前打开的文件，必要时读同仓其它篇。
- 产品经理主文件默认是 `PRD.md`；不要拆成 01–05，除非对方明确要求。

硬规则里**不要**再写死四档行为、OEM 检查表、必须 `clarity: ready`。那些若还需要，写进默认系统提示词，让架构师能删。

### 4.2 系统提示词文件

| 项 | 规定 |
|----|------|
| 路径 | `<workspaceRoot>/.dw/system-prompt.md` |
| 首次 | 根目录设定后，若不存在则从内置默认拷入 |
| 编码 | UTF-8 |
| 权限 | GET/PUT 仅架构师；Agent 跑的时候服务端读盘，不经产品经理 API |
| 恢复默认 | 用内置默认覆盖文件 |
| 空文件 | 视为「只要硬规则」；允许。不要偷偷写回默认 |

内置默认文案放 `packages/templates/system-prompt.md`（实现 G1 时落盘）。出厂口味可以仍提五章 PRD、一次问 1～3 个问题、缺口进 `gaps.md`——这是默认，不是法规。

### 4.3 API

与现有 `/v1/workspace` 同级：

- `GET /v1/workspace/system-prompt` → `{ text, isDefault }`（架构师）
- `PUT /v1/workspace/system-prompt` body `{ text }`（架构师）
- `POST /v1/workspace/system-prompt/reset` 恢复默认（架构师）

未设 `workspaceRoot`：`409` 或 `400`，中文：`请先选定运行根目录。`

## 5. 规格：选区与本轮焦点

### 5.1 数据

```ts
type DocFocus = {
  file: string;          // 相对文档仓，如 PRD.md
  headingPath: string[]; // 如 ["用户故事", "US-001"]
  quote: string;         // 选中原文，可空
};
```

不要用 DOM 偏移、不要给模型行号（改完即失效）。定位 = 章节路径 + 引文。引文在文件中出现多次时，模型用 `headingPath` 收窄；仍歧义就问人。

### 5.2 墨览要补的能力

现状：`EditorApi` 只有 `getValue` / `setPreview` 等，**没有选区**。且人活在预览里，选区必须在**预览态**可用。

协议（可走 `FrameToHostMessage` 或 inline host 回调，三端尽量同一套）：

- 事件 `selection`：`{ headingPath, quote }`（`quote` 空表示取消）
- 预览态 `window.getSelection()` 非空松手即上报
- 点标题：取该标题到下一同级/更高级之前的纯文本为 `quote`，`headingPath` 为祖先标题 + 自身
- 宿主高亮由墨览做；工作台只收数据、画芯片

不把稳定 block id 写进 Markdown。

### 5.3 发给模型的 user turn

替换 `workbenchAgent.ts` 里按 `mode` 拼的 `userPrompt`。形状：

```text
工程：{title}
打开的文件：{file}
文档仓还有：{inventory}

## 焦点
章节：{headingPath 用 / 拼接，或「（整篇）」}
选中原文：
{quote 用 markdown 引用；空则写「（无选区，对整篇）」}

## 对方说
{message}

先读文档仓里已有的 Markdown（至少打开的这篇），再用中文说明你在做什么，然后读写文件。有选区就先定位到引文再改。
```

托付 API 增加可选 `focus: DocFocus`。缺省 = 对当前打开文件整篇。

## 7. 拆解：一次只做一刀

原则：每一刀能独立合并；有测试或可手测步骤；做完更新 §11；**不要**把 G3 和 G4 绑在一次 PR。

### G1 系统提示词存盘 + API + 设置

**做：**

- 内置默认：`packages/templates/system-prompt.md`
- 读写 `<workspaceRoot>/.dw/system-prompt.md`
- 设定 `workspaceRoot` 时若不存在则拷贝默认
- `GET/PUT/reset` 三个接口，ACL = 架构师

**不做：** 改 Agent 拼接（G2）、改 UI 档位（G3）。

**过关：** 架构师保存后磁盘上就是那份 Markdown；产品经理 403。
