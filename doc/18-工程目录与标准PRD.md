## 1. 角色

```text
架构师
  设定服务运行根目录（所有设计工程都建在这下面）
  从 ~/.claude.json 扫入本机工程，批准其中一部分给 AI 用
  管账号 / Claude / MCP
  也可建工程、删工程、解除编辑权

产品经理
  在根目录下自己建工程（一个子文件夹）
  不选、不看代码路径
  填模板或导入，围着文档包和 AI 做设计
```

架构师不再给每个工程选文档目录，也不再给每个工程勾代码仓。根目录未设定时，产品经理不能建工程；空纸面上只留一句，不做成说明页。

**删除：** 只有架构师能删；动作 = 删掉该子文件夹（含 `.git`）。产品经理不能删。

**可见性：** 根目录下所有工程全员可见。

界面写「产品经理」。代码角色值仍是 `designer`。

## 2. 目录即工程

工程列表不靠数据库。架构师设定 `workspaceRoot` 之后，每个子文件夹就是一个工程。丢掉 SQLite 仍能扫盘恢复列表；丢掉文件夹等于丢掉工程。

```text
<workspaceRoot>/                    # 架构师在设置里选定
  设置页夜间模式/                    # 文件夹名 = 工程名（允许中文）
    PRD.md                          # 产品经理唯一主文件（各章用 ## 分隔）
    meta.md
    gaps.md                         # AI 维护，可建可改
    import/                         # 仅导入路径
      original.md
    调研.md                         # 可行性跑完才出现，不进初始模板
    .git/
    .dw/                            # 可重建运行态，gitignore
  负一屏天气卡片/
    ...
```

- 列表 = 扫描根目录下带 `meta.md` 的子目录。
- 文件夹名用工程标题，去掉 `/ \ : * ? " < > |`。重名则 `名称-2`。
- `meta.md` 写稳定 `id`（短 nanoid），路由用 id，改名不炸链接、不打散编辑权。
- SQLite 只留用户、锁、runs；工程列表可留扫盘缓存，丢掉也能重建。
- 每个子文件夹仍是独立 Git 文档仓：保存 ≠ 记入版本；AI 一轮成功自动 commit，作者名 `AI`。

`arch/`、`qa/` 本阶段不初始化。

## 3. 标准 PRD：单文件 PRD.md

**2026-09-01 拍板：** 产品经理只改一篇 `PRD.md`。各章用 `##` 标题分隔，不拆成 01–05 多文件。AI 一次 Read 成本低，Git diff 仍可按章节看。

| 文件 | 谁写 | 写什么 |
|------|------|--------|
| `PRD.md` | **产品经理**（AI 共创 / 拷问时可写回对应章节） | 一句话目标 + 五章：`## 背景与目标` / `## 用户故事` / `## 交互与体验` / `## 规格与约束` / `## 验收` |
| `gaps.md` | AI | 待补齐清单，对应到 PRD.md 章节。不对外展示给最终读者 |
| `meta.md` | 系统 + AI（clarity 过关时） | id、title、owner、source（template / import）、phase、clarity |
| `import/original.md` | 系统（导入路径） | 粘贴 / 上传的原文，只读参照 |
| `调研.md` | AI（可行性档位） | 用了哪些代码目录、已有能力 / 缺口 / 风险 / 建议 |

用户故事固定形态（写在 `PRD.md` 的 `## 用户故事` 下）：

```text
### US-001 （标题）

- 作为：
- 我想要：
- 以便：
- 验收：
  - [ ] （可观察、可判定的一条）
```

模板放 `packages/templates/prd-pack/PRD.md`，不要写在代码字符串里。每节给填写说明 + `（待补充）`。

## 4. 两条创建路径

同一纸面上打开新建面板：工程名 + 「从模板填写」或「导入 PRD」。不选文档目录，不选代码仓。创建后打开 `PRD.md`。

### 路径 A：模板

1. 建文件夹，拷入 `PRD.md` + `meta.md`，`source: template`，`phase: filling`。
2. 人在墨览把各 `##` 节填完。这阶段不开放可行性。
3. 跟设计类 AI 对话之前，先跑「检查清晰度」。AI 只读 `PRD.md`，按检查表标清晰 / 缺失 / 含糊，写入 `gaps.md`，一次追问 1～3 个问题，人答完写回 PRD.md 对应章节。
4. 必填节不再是占位、没有会改设计的含糊句，才把 `meta.md` 的 `clarity: ready`，解锁共创 / 拷问 / 可行性。

「清晰」≠「能开发」。标准是无歧义、可开始设计讨论。占位符、纯「等」「看情况」、用户故事缺验收、主流程有头无尾、规格和故事打架，都不算过。

### 路径 B：导入

1. 粘贴或上传（不做 URL 抓取）。原文只进 `import/original.md`。
2. 立刻做一次规范化：按 PRD.md 五章拆写进对应 `##` 节，不编造事实；对不上的进 `gaps.md`，对应节留 `（待补充）`。
3. 默认档位是「检查清晰度」（`clarify`）。后续对话仍先看 `gaps.md`，缺的就要求人补。
4. 同样要过 `clarity: ready` 才解锁可行性。共创可以边补边写；发送时若仍有 P0 缺口，必须先问，不能假装已经齐。

## 5. 清晰度门闩

现有三档之上加 **检查清晰度**（`clarify`）。

| 阶段 | 可用档位 |
|------|----------|
| `filling` / `imported` / `clarifying` | 仅检查清晰度（「帮我把这一节写清楚」也走这套提示词） |
| `ready` | 共创、拷问、可行性 |

可行性还要求架构师至少批准过一个代码目录。未就绪时顶栏只有一点状态，不铺横幅。发送关卡沿用 [12](./12-实现前决策.md)：持编辑权、不在编辑态、git 干净、没有进行中的一轮。

检查表覆盖：背景与用户、目标与非目标、至少 1 条完整用户故事、至少 1 条主流程、入口、规格与 OEM 约束、整包验收。导入路径额外对照 `import/original.md`。

OEM 必问维度仍听 [06](./06-OEM产品经理场景与实现决策.md) §5。

## 6. 代码目录：扫入、批准、AI 选用

代码目录是**服务级资源**，与产品经理工程脱钩，不写进工程 `meta.md`。

**来源只有 `~/.claude.json`。** 设置里扫入 Claude 已登记的工程，架构师批准其中一部分。不浏览磁盘、不手补路径、不把扫到的默认全开。再扫一次时，新出现的默认未批准。取消批准即从 AI 可用集合拿掉。全部只读。

产品经理创建、打开、对话都不出现目录列表。需要读代码时，AI 从已批准的目录里自己识别：

1. **目录卡**（可重建）：已批准目录的文件夹名、路径、README / 清单头几行。
2. **本轮选用**：先对照目录卡挑若干个，再只对选中的 Read / Grep。问产品问题消歧，不问「要用哪个 Git 仓库」。
3. **写回**：用了哪些、为什么，写进 `调研.md`。这是 AI 产出，不是创建必填。

一个都没批准时，可行性不可用，发送时说一句「架构师还没批准代码目录」。Agent 的 `additionalDirectories` 只用本轮选中的，不要把全部已批准目录灌进每一次 run。禁止改业务代码。

## 7. 界面：单页、全屏、对齐墨览

对齐墨览指空间和发现方式，不是再做一遍编辑器。Web 仍 inline 挂墨览，保留 `reader-header`（见 [16](./16-墨览现状.md)）。

打开就是全视口。主区即纸面。次要能力用 icon、菜单、浮层发现，不把每个按钮和提示写在脸上。

```text
同一壳 · 全视口
┌ 细 rail（可收成 icon）─┬ 墨览纸面铺满 ─────────────────────┐
│ 工程 / 文档              │  reader-header：篇名 · 保存态 · ··· │
│                          │                                     │
│                          │  正文（唯一大面积）                  │
│                          └────────────── 托付底条（收起） ─────┘
└ 设置 / 用户 / 新建 = 同一壳上的浮层 ──────────────────────────┘
```

| 面 | 怎么出现 | 不要做成 |
|----|----------|----------|
| 工作台 | 默认；登录后进最近工程，没有则空纸面 | 先落到窄列表站 |
| 换工程 | rail 或命令面板 | 回「首页」再跳另一个页面 |
| 新建 | 纸面上的轻面板：名称 + 模板 / 导入 | 分步向导、选目录 |
| 设置 / 用户 | 架构师从 `···` 打开浮层 | 独立后台表单页 |
| 版本 / 导入 / 对比 | 抽屉或遮罩 | 常驻按钮条 |
| 登录 / 首次建号 | 允许单独一面，仍全屏少 chrome | 小卡片旧后台登录 |

纸面占主：去掉站点 max-width、外圈厚垫、中栏第二层圆角壳。文件名和保存态只出现在墨览顶栏一处。AI 是托付浮层（收起 / 半幅 / 铺满），人改时收成底条。视觉继续用宣纸 / 墨夜 / 终端 / 胭脂，不上仪表盘风。

| 能力 | 默认看见 | 怎么发现 |
|------|----------|----------|
| 写文档 | 纸面 | 打开即是 |
| 跟 AI 说一句 | 底条一个输入 | 展开才见档位、进度 |
| 清晰度 | 顶栏一点状态 | 点开或被拦住时才看缺口 |
| 代码仓 | 无 | 架构师设置里批准；结论在调研里 |
| 记入版本 / 对比 / 撤销 | 无 | header `···` 或「版本」 |
| 导入、删工程、解除编辑权 | 无 | 菜单 |

## 8. 同一工程只有一个写者

与 [11-3](./11-设计稿-3-Git与文档同步.md)、[12](./12-实现前决策.md) 一致。锁的是编辑权，不是进门。

1. **人与人：** 同一时刻只有一个持有者能改文档、开 AI、取消本轮。别人可进，只读预览，跟上磁盘和 AI 进度。
2. **人与 Agent：** 持有者不能边改边托付。同一时刻只有一个写者。AI 在跑时纸面只读。

实现沿用现有：`project_locks` 一行一工程；`clientId` 在 `sessionStorage`（同账号另一浏览器预览，不抢锁）；打开即 claim；心跳约 20 秒；关页且无进行中 run 则释放；无心跳约 2 分钟且无 active run 则过期；AI 在跑不放锁；写文件走 `assertWritable`；开 AI 还要未在编辑态、git 干净、没有 `queued/running`；只有架构师能解除编辑权（对方变成预览）。

界面只留一句短提示，不铺锁说明书。`project_id` 用 `meta.md` 的稳定 id。

## 9. 下一刀：AI 全链路（当前优先）

壳、扫盘、模板、门闩骨架已在代码里。**下一刀验收**是四条 AI 档位从「能点」到「能日用」，不靠 mock 糊弄。

### 9.1 链路概览

```text
模板 / 导入 → 填 PRD.md
        ↓ clarify（写 gaps.md，过关改 meta clarity: ready）
   共创 / 拷问（写回 PRD.md + gaps.md）
        ↓ 架构师已批准代码目录
   可行性（只读代码 → 写 调研.md）
        ↓ 每轮成功
   自动记入版本（作者 AI）
```

### 9.2 分档验收

| 档位 | 输入 | AI 应做 | 过关标志 |
|------|------|---------|----------|
| **clarify** | PRD.md（+ import/original.md 若导入） | 按检查表写 gaps.md；追问 1～3 个；人答后写回 PRD 对应 `##` 节 | 全部过关时 AI 改 meta.md → `clarity: ready`；UI 解锁共创 / 拷问 |
| **coauthor** | 用户一句话 + 现有 PRD | 更新 PRD.md 对应章节；未决进 gaps.md | 纸面可见改动；一轮成功自动记版 |
| **grill** | 用户怀疑点 | 追问矛盾 / 隐含假设；写入 gaps.md；确认内容写回 PRD | 同上 |
| **feasibility** | 用户问题 + 已批准代码目录 | 对照目录卡选用仓；Read/Grep 只读；结论写 调研.md | 信任条列出本轮只读目录；不改业务代码 |

### 9.3 横切能力（每档共用）

1. **发送关卡**：持编辑权、不在编辑态、git 干净、无进行中 run；被拦时消息留在输入框（[12](./12-实现前决策.md)）。
2. **门闩**：未 ready 时只有 clarify；无批准代码目录时 feasibility 灰掉并人话提示。
3. **Run 生命周期**：POST 立刻返回 runId；SSE 可重放 + 直播；关页可续订；取消不等于关页。
4. **纸面跟随**：AI 进行中墨览只读；磁盘变了树和预览跟上。
5. **真实模型**：配好本机 Claude / API Key 后走 Agent SDK，mock 仅作无密钥演示。

### 9.4 建议实现顺序

1. clarify 端到端：模板工程 → 跑一轮 → gaps.md 落地 → meta ready → 档位解锁
2. coauthor / grill：写回 PRD.md 章节 + 自动记版
3. feasibility：代码目录选用 + 调研.md + 信任条
4. 导入路径：original.md → 拆进 PRD 五章 + gaps，再走 clarify
5. 前端 polish：顶栏清晰度状态、被拦提示、gaps 快捷入口

每一刀单独验收。编辑器不重做。安装包排在 AI 全链路能日内跑通之后。
