# 客户端架构

> 状态：已拍板 · 2026-08-15  
> 工程怎么建、界面怎么铺，以 [18](./18-工程目录与标准PRD.md) 为准。本文只谈服务器、ACL、文件写回、session。  
> 配套：[00-产品重定位.md](./00-产品重定位.md)

## 1. 一句话

**安装程序把一台机器变成服务器；人用浏览器工作；架构师和产品经理只是账号权限不同。** 浏览器关掉，任务还可以跑。

不需要 Tauri 工作台。角色差的是 ACL，不是两个客户端。

## 2. 分层

```text
安装包
  └── 本机服务器（开机可启动，内置 Node）
        ├── Web UI（墨览 + 工程 + Agent + 设置页）
        ├── API + 用户 / ACL
        ├── 文件目录与监视
        └── 调度 Claude Code
              ▲
架构师 / 产品经理 ──浏览器──▶ 同一套 UI
```

现有 `apps/agent` + `apps/web` 就是这套的雏形：装成服务、加上用户和 ACL，而不是再包一层桌面壳。

### 2.1 用户与 ACL

| 权限 | 架构师 | 产品经理 |
|------|--------|----------|
| 登录工作台、建工程、编辑文档、开 Agent | 是 | 是（不能删工程） |
| 设置运行根目录、从 claude.json 批准代码目录 | 是 | 否 |
| 设置 Claude / Key、MCP/skills 开关 | 是 | 否 |
| 创建/停用账号 | 是 | 否 |
| 看密钥、改监听地址 | 是 | 否 |

实现：同一 HTTP API，管理类路由校验角色（例如 `requireRole("architect")`）。不要靠「换客户端」或「另开一个只有本机才有的端口」来分权——两边都是浏览器，分权必须在服务端。

安装后的第一个用户 = 架构师。产品经理账号由架构师创建。

设置对产品经理：菜单不显示，接口也返回 403。

开源怎么接（建议）：

- **用户 / 登录：** [Better Auth](https://www.better-auth.com/)（MIT、TypeScript、可走现有 SQLite）。管密码、session、Cookie。官方有 [admin](https://www.better-auth.com/docs/plugins/admin) / [organization](https://www.better-auth.com/docs/plugins/organization) 插件；第一版用 admin + 两个角色即可，不必上「多组织」。
- **授权：** 不要上 Casbin / OpenFGA / Keycloak。两种角色用 `user.role` + `requireRole("architect")` 就够。前端藏菜单可用 [CASL](https://casl.js.org/) 的 `can()`，但决定权仍在服务端。
- **不做：** Auth0/Clerk（数据出本机）、Keycloak/Authentik/Logto（为这两种角色开一套 IdP）。

角色映射：安装后第一个账号 = `architect`；邀请的产品经理 = `designer`。

### 2.2 环境

一台已安装并启动的服务器 = 一个环境：托管机上的 Claude/MCP（默认全开）、运行根目录、已批准代码目录、用户表。

产品经理拿到的是 URL 和账号，不是安装包。只有需要托管后台的人装安装程序。

### 2.3 安装程序做什么

- 带上 Node 运行时和 Web/Agent  
- 注册为用户级服务或「登录时启动」（macOS `launchd`，Windows 服务或开机启动）  
- 首次启动：创建架构师账号、扫 `~/.claude`、打开浏览器到本机地址  
- 不强制托盘；文档写清如何停服务即可  

选目录用 **服务器端目录树 API**（列托管机文件夹），因为浏览器选文件夹选的是访问者自己的电脑，对不上代码仓所在盘。

### 2.4 从 AgentScope 抄什么（不引入它的运行时）

抄 **Agent Service 的多用户形状**，引擎仍是 Claude Agent SDK，Web 仍是墨览。不要把 Python AgentScope 嵌进来。

| 抄 | 不抄 |
|----|------|
| 每个请求有 `user_id`；资源挂在用户下 | 它自带的用户系统（它只留 `X-User-ID` 钩子，我们自己做账号 + ACL） |
| Session 是运行态；`POST /chat` 立刻返回；`GET /sessions/{id}/stream` 可重放 | 把 PRD 放进 **per-session workspace**。文档根是人共享的真相，不是 Agent 一次性沙箱 |
| 工作区隔离可配置（我们：文档根共享可写、代码根只读） | Docker / E2B 沙箱当主存储 |
| MCP/skills 挂在环境上，按角色改 | 它的整站 Web UI |

AgentScope 的 `GET /workspace/files` 是给 Agent 浏览沙箱、发下载 token 用的，**不是**给人在所见即所得里改完写回的协议。

## 3. Session：任务的身份证

参考 [AgentScope 2.0 Agent Service](https://docs.agentscope.io/v2/deploy/agent-service) 的模型，**不引入 AgentScope 运行时**。引擎仍是 Claude Agent SDK。

要抄的是：

| 概念 | 含义 |
|------|------|
| `session_id` | 一次对话/任务的稳定 id，与 HTTP 连接无关 |
| 发消息立刻返回 | `POST` 只表示「已入队 / 已开始」，不等 Agent 跑完 |
| 事件流可重放 | `GET /sessions/{id}/stream?after=seq`，晚到的界面先补历史再接直播 |
| 取消 | `POST /sessions/{id}/cancel`，关窗口不等于取消 |
| 状态 | `idle` → `running` → `idle` / `error`；可暂停等人采纳文档 |

当前实现的差距：`POST /sessions/:id/messages` 占着这条连接跑完全程，前端一断就 `AbortController` 掐掉 Agent。可行性分析扫多个仓时不可接受。

本地第一版用 **SQLite + 事件日志文件** 持久化 session，不必上 Redis。协议按可重连来写，云端多实例再换共享存储。

事件类型建议采用 **AG-UI 子集**（`threadId` = `session_id`），见 [08-Agent对话UI选型.md](./08-Agent对话UI选型.md)。传输用 AgentScope 那种「session 流」而不是「一次 POST 占满连接」。

### 3.1 和 Claude 怎么接

一个 session 绑一个工程，因此自动知道：

- 可写范围 = 当前工程文件夹
- 只读范围 = 本轮 AI 选用的已批准代码目录
- Agent `cwd` = 工程文件夹
- 代码目录经 SDK `additionalDirectories` 只读挂入（Read / Glob / Grep）

凭证：服务启动时扫托管机 `~/.claude`；**默认全开** MCP / skills。没有凭证则架构师在设置里填 Key。产品经理不碰这一层。工程与代码目录怎么绑，见 [18](./18-工程目录与标准PRD.md)。

## 4. 工程与文件目录

工程模型以 [18](./18-工程目录与标准PRD.md) 为准：运行根目录下每个子文件夹一个工程；代码目录是服务级批准名单，不挂在工程上。

墨览只打开当前工程文件夹里的文件。侧栏是工程文档树，不是某个 Git 仓的原样树。正文永远在磁盘 Markdown 上，见 [04](./04-文档存储原则.md)。

未批准任何代码目录：工程仍可建，可行性不可用。默认不改业务代码。

### 4.1 墨览怎么读远端 md、怎么存回去

浏览器里的文件对用户是「远端」，对服务器是本机磁盘。墨览 **不负责落盘**（和 VS Code 扩展一样：编辑器只 `getValue` / `setValue`，写盘是宿主）。

**现成做法就是 HTTP 文件资源 + 冲突检测，没有更好的专用库要引。**

```text
打开  GET  /v1/files?project=…&path=PRD.md
      → { content, etag }          etag = mtime 或内容 hash

保存  PUT  /v1/files?… 
      If-Match: <etag>
      body: markdown
      → 200 + 新 etag
      → 409 若磁盘已被别人或 Agent 改过
```

这就是 WebDAV/`If-Match`（RFC 7232）那一套。VS Code 自定义编辑器、Nextcloud 打开 md，都是这个。仓库里已经有半套：`PUT /v1/requirements/:id/prd`、VS Code 里 `workspace.fs.writeFile`。

Agent 改了同一篇时：只读跟上磁盘。人 XOR AI 之后正常不会和 AI 抢同一篇。etag 对不上：请重新打开这篇，不做三选一。

不要用的：

| 方案 | 原因 |
|------|------|
| 浏览器 File System Access / 系统「另存为」 | 选的是访问者自己的电脑，不是托管机文档根 |
| AgentScope workspace 写文件当人的保存 | 沙箱按 session 隔离，人对不上同一篇 PRD |
| HedgeDoc / Yjs 实时协同 | 已明确不做多人同时改一篇的协同 |
| Git CMS（Tina / Decap） | 保存变成 commit，和「文档根就是文件夹」不一致 |
| 给文档根挂 WebDAV 给 Typora 用 | 旁路可以以后再加，工作台不依赖它 |

第一刀：`GET/PUT /v1/files` + `If-Match`，ACL 为「文档根可写」。墨览 Cmd+S 调 PUT。

## 5. 安装之后本机有什么

| 能力 | 谁来做 |
|------|--------|
| 以服务方式常驻、开机启动 | 安装程序 |
| 打开浏览器进工作台 | 安装结束或快捷方式 |
| 设运行根目录、批准代码目录 | 架构师 |
| MCP / skills 开关 | 架构师 + ACL |
| 监视工程文件夹、刷新墨览 | 服务器 |
| 建工程、写文档、开 Agent | 架构师和产品经理 |
