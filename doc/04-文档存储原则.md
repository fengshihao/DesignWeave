# 文档存储原则

> 状态：已拍板 · 2026-08-15 · 2026-08-22 目录树按 [18](./18-工程目录与标准PRD.md) 修订  
> 结论：**Markdown 目录 = 主文档真相源；SQLite = 辅助运行态。**  
> 工程 = 运行根目录下的一个子文件夹。不写进代码仓。

## 1. 为什么这样

| 收益 | 说明 |
|------|------|
| 可 Git | 每个工程文件夹单独成仓；与业务 Git 隔离 |
| 可旁路打开 | 用墨览 / VS Code / Typora 直接改 |
| 与 Claude 友好 | Agent 本就会 Read / Edit 文件 |
| 不碰业务仓 | 代码目录只读；产品经理不会把 PRD 提交进业务仓 |
| 列表可重建 | 扫盘子文件夹即可；删工程 = 删文件夹 |

正文用 Markdown；元数据用 YAML frontmatter。链接用相对路径。大附件放 `assets/`。

## 2. 目录

见 [18](./18-工程目录与标准PRD.md) §2 / §3。标准包是 `PRD.md`（各章 `##` 分隔）、`meta.md`；AI 维护 `gaps.md`；导入原文在 `import/`；可行性产出 `调研.md`。`arch/`、`qa/` 本阶段不建。

代码目录**不在**文档树里，也不写进工程 `meta.md`。它们是服务级已批准名单。

`gaps.md` 继续用**单文件**（[12](./12-实现前决策.md)）。

## 3. SQLite 只做什么

- 用户 / 登录
- 编辑权锁、Agent run / 事件
- 可选：扫盘缓存、UI 偏好、FTS

不适合当主存储：PRD 正文、任何要给人审阅或进 Git 的内容。

原则：**丢掉 SQLite 后，扫盘仍能恢复工程列表；丢掉 Markdown 则不可接受。**

## 4. 界面与文件

```text
墨览编辑 ──保存──▶ 写工程文件夹 .md
外部编辑器改文件 ──刷新/监视──▶ UI 重读
Agent 修订 ──Edit/Write──▶ 同一批 .md（仅该工程文件夹）
```

UI 是文件的视图，不是第二个数据库。保存 ≠ 记入版本。旁路改盘导致 etag 对不上：请重新打开这篇，不做「留我的 / 用磁盘的」。
