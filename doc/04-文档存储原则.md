# 文档存储原则（Obsidian 式）

> 状态：已拍板方向 · 2026-08-15  
> 结论：**Markdown 目录 = 主文档真相源；SQLite = 辅助索引/session/运行态。**  
> 文档落在工程的 **专有文档根**，不写进代码仓。见 [07-客户端架构.md](./07-客户端架构.md)。

## 1. 为什么适合 DesignWeave

和 Obsidian「文件夹 + Markdown」同一套心智：

| 收益 | 说明 |
|------|------|
| 可 Git | 文档根可以单独成仓，或人拷到评审目录；与业务 Git 隔离 |
| 可旁路打开 | 用墨览 / VS Code / Typora 直接改，不锁死在客户端 |
| 与 Claude 友好 | Agent 本就会 Read/Edit 文件；少一层 ORM 翻译 |
| 不碰业务仓 | 代码根只读；产品经理不会把 PRD 提交进 SettingsApp |

当前 MVP 里同时有 `prd.json` + `PRD.md`，长期应以 **Markdown（+少量 frontmatter）为主**，JSON 仅在确有结构化需要时作 sidecar 或逐步淘汰。

## 2. 推荐目录（专有文档根）

```text
<文档根>/                          # 如 ~/Documents/DesignWeave/设置页夜间模式/
  README.md
  meta.md                          # 工程名、代码根列表、阶段
  PRD.md
  gaps.md
  import/
    original.md
  arch/
    TECH_SPEC.md
    srs/
      SR-001.md
  qa/
    TEST_PLAN.md
    cases/
      TC-001.md
  .dw/                             # 索引、session 副本（可重建，可 gitignore）
```

代码根是另一些目录，**不在文档树里**，只出现在 `meta.md` 和 SQLite 索引中。

约定：

- **一个工程一个文档根**；第一版先一个工程一份 PRD，不必再套 REQ- 子文件夹  
- 正文用 Markdown；元数据用 YAML frontmatter（status、phase、owner、updated）  
- 链接用相对路径（第一版不用 wikilink）  
- 大附件放 `assets/`，不进 SQLite

## 3. SQLite 只做什么

适合放「不是文档正文」的东西：

- 工程列表索引（文档根、代码根、标题、阶段、更新时间）——可由扫盘重建  
- Agent session / 事件日志索引、取消状态、run id  
- UI 偏好、最近打开  
- 可选：全文搜索 FTS 缓存（文件变更后增量重建）

**不适合**放进 SQLite 当主存储：

- PRD / 技术方案 / SR / 测试方案正文  
- 长期要给人审阅、导出、进 Git 的内容  

原则：**丢掉 SQLite 后，用扫盘仍能恢复工作台列表；丢掉 Markdown 则不可接受。**

## 4. 界面与文件的关系

```text
墨览编辑 ──保存──▶ 写文档根 .md
外部编辑器改文件 ──刷新/监视──▶ UI 重读
Agent 修订 ──Edit/Write──▶ 同一批 .md（仅文档根）
```

- UI 是文件的视图与工作流，不是第二个数据库  
- 保存策略：显式保存或短防抖；避免与外部编辑器狂冲突（可用 mtime 提示）  
- 「采纳 AI 修订」= patch 进对应 md 段落/文件  

## 5. 与现有实现的迁移方向

| 现状 | 目标 |
|------|------|
| `data/workspaces/<id>/prd/prd.json` 或仓内 `.designweave/` | 用户选定的 **文档根** 内 `PRD.md` 等 |
| `issues.json` | `issues.md` 或 `issues/*.md` |
| SQLite 存项目主数据 | SQLite 降为索引 + session + 运行态 |
| 导出 PRD.md | **本身就是 md**，导出=打包/复制目录 |

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 本机多窗口改同一文件 | 保存前比对 mtime；后台监视文档根 |
| Markdown 结构漂移 | 章节标题约定 + Agent 按标题写入；可选 frontmatter schema |
| 扫盘性能 | SQLite 索引缓存；文件 watcher 增量更新 |
| 密钥进库 | 文档与 vault 禁止写入 token；.gitignore 模板提供 |
