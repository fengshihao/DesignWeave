# 文档存储原则（Obsidian 式）

> 状态：建议采纳 · 2026-08-09  
> 结论倾向：**Markdown 目录 = 主文档真相源；SQLite = 辅助索引/会话/状态。**

## 1. 为什么适合 DesignWeave

和 Obsidian「文件夹 + Markdown」同一套心智：

| 收益 | 说明 |
|------|------|
| 可 Git | PRD / 技术方案 / SR / 测试方案可随工程评审、diff、回滚 |
| 可旁路打开 | 设计师用 Obsidian / VS Code / Typora 直接改，不锁死在 Web UI |
| 与 Claude 友好 | Agent 本就会 Read/Edit 文件；少一层 ORM 翻译 |
| 跟工程走 | 默认落在 `\<repo\>/.designweave/`，换机器/备份都简单 |
| 小服务器场景 | 多人浏览器写的仍是服务器磁盘上的 md，权限清晰 |

当前 MVP 里同时有 `prd.json` + `PRD.md`，长期应以 **Markdown（+少量 frontmatter）为主**，JSON 仅在确有结构化需要时作 sidecar 或逐步淘汰。

## 2. 推荐目录（工程内 Vault）

```text
<repo>/
  .designweave/
    README.md                 # 本工程 DesignWeave 说明
    requirements/
      REQ-001-短标题/
        meta.md               # frontmatter：状态、负责人、阶段
        PRD.md                # 主 PRD（人读为主）
        issues.md             # 拷问/自洽问题（也可拆 issues/*.md）
        arch/
          TECH_SPEC.md
          srs/
            SR-001.md
            SR-002.md
        qa/
          TEST_PLAN.md
          cases/
            TC-001.md
    _inbox/                   # 未绑定工程前的草稿（可选，服务器全局另议）
```

约定：

- **一个需求一个文件夹**，文件夹名稳定 ID + 短标题  
- 正文用 Markdown；元数据用 YAML frontmatter（status、phase、owner、updated）  
- 链接用相对路径 / Obsidian 式 `[[PRD]]`（第一版可先只用相对路径）  
- 大附件放 `assets/`，不进 SQLite

## 3. SQLite 只做什么

适合放「不是文档正文」的东西：

- 需求列表索引（路径、标题、阶段、更新时间）——可由扫盘重建  
- 登录会话 / 口令哈希（小服务器鉴权）  
- Agent 运行记录、取消状态、队列任务 id  
- UI 偏好、最近打开  
- 可选：全文搜索 FTS 缓存（文件变更后增量重建）

**不适合**放进 SQLite 当主存储：

- PRD / 技术方案 / SR / 测试方案正文  
- 长期要给人审阅、导出、进 Git 的内容  

原则：**丢掉 SQLite 后，用扫盘仍能恢复工作台列表；丢掉 Markdown 则不可接受。**

## 4. Web UI 与文件的关系

```text
浏览器编辑 ──保存──▶ 写 .md 文件
Obsidian/编辑器改文件 ──刷新/监听──▶ UI 重读
Agent 修订 ──Edit/Write──▶ 同一批 .md
```

- UI 是文件的视图与工作流，不是第二个数据库  
- 保存策略：显式保存或短防抖；避免与外部编辑器狂冲突（可用 mtime 提示）  
- 「采纳 AI 修订」= patch 进对应 md 段落/文件  

## 5. 与现有实现的迁移方向

| 现状 | 目标 |
|------|------|
| `data/workspaces/<id>/prd/prd.json` 为主 | `\<repo\>/.designweave/requirements/REQ-*/PRD.md` 为主 |
| `issues.json` | `issues.md` 或 `issues/*.md` |
| SQLite 存项目主数据 | SQLite 降为索引 + 鉴权 + 运行态 |
| 导出 PRD.md | **本身就是 md**，导出=打包/复制目录 |

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 多人同时改同一文件 | 保存前比对 mtime；后期可加简单锁/提示 |
| Markdown 结构漂移 | 章节标题约定 + Agent 按标题写入；可选 frontmatter schema |
| 扫盘性能 | SQLite 索引缓存；文件 watcher 增量更新 |
| 密钥进库 | 文档与 vault 禁止写入 token；.gitignore 模板提供 |
