# Claude Code 配置复用与工程绑定

> 运行形态见 [00](./00-产品重定位.md)、[07](./07-客户端架构.md)

## 1. 目标

在架构师托管后台的那台机器上复用已配好的 Claude Code（skills / MCP / 企业工具）。产品经理不自己配 Claude。

**B3：** MCP / skills **默认全开**。启动时扫到的一律启用；架构师可在设置里关。没有「首次逐项勾选」向导。

## 2. 启动时扫描

```text
服务启动 → 检测 Agent SDK / claude CLI
        → 扫描 ~/.claude/settings.json 与 ~/.claude.json
        → MCP / skills 默认全开
        → 设置里展示摘要（不展示密钥）
```

设置只读展示：是否发现 Claude 配置、语言偏好、MCP / plugins 名称、Claude 已登记的本地工程路径、本机能否跑 Agent SDK。

## 3. 代码目录：只从 claude.json 来

与产品经理工程**脱钩**。名单在服务配置里，不在某个工程的 `meta.md`。

1. 从 `~/.claude.json` 扫入已登记路径。
2. 架构师批准其中一部分。扫到的默认不全开。
3. 不浏览磁盘、不手补路径。
4. 再扫时，新出现的默认未批准；取消批准即从 AI 可用集合拿掉。
5. 全部只读。

产品经理不选、不看这些路径。需要读代码时，AI 从已批准目录里自己识别，选用结果写进 `调研.md`。问产品问题消歧，不问「要用哪个仓库」。

一个都没批准：工程仍可建，可行性不可用。

Agent：`cwd` = 当前设计工程文件夹；`additionalDirectories` = **本轮选中**的已批准目录，不要把全部已批准目录灌进每一次 run。禁止写代码目录。

## 4. 安全与合规

- 不把 `ANTHROPIC_AUTH_TOKEN` 等写入文档工程或导出物
- 日志脱敏
- 后台管理 API 鉴权；不对公网
- 产品经理登录态不能调用管理接口
- 会话状态可放 SQLite；正文永不进库当唯一副本
