## B. Claude 与工程

- [x] **B1** 文档默认落盘与存储形态  
  - 结论：_每个工程一个专有文档目录（Markdown 真相源）；代码仓全部默认只读；SQLite 仅索引/session/运行态（见 [04](./04-文档存储原则.md)、[07](./07-客户端架构.md)）_

- [x] **B2** 无代码仓能否创建工程？（纯概念 PRD）  
  - 结论：_允许只有文档根；持续提醒绑定代码根；可行性分析禁用_

- [x] **B3** MCP/skills 默认「全部复用」还是首次逐项确认？  
  - 结论：_默认全开（复用托管机 `~/.claude`）。架构师可在设置里关；产品设计不能改。无首次勾选向导_

## C. UX

- [x] **C1** 设计阶段是否采用「收集 → 成文 → 拷问」三步，而不是永久双栏聊天？  
  - 结论：_共创 / 拷问 / 可行性是右侧三个档位，主区永远墨览。06 F7「引导时主区是对话」已过时。见 [11-4](./11-设计稿-4-综合与待拍板.md)、[12](./12-实现前决策.md)_

- [x] **C2** 首屏结构  
  - 结论：_登录后进工作台。架构师多「设置 / 新建工程 / 用户」。产品设计只有已有工程_

- [x] **C3** 架构/测试未就绪时：隐藏入口，还是显示锁定进度？  
  - 结论：_本迭代隐藏_

- [x] **C4** 文档同步：人与 AI 能否同时改？多人能否同时打开同一工程？  
  - 结论：_同一时刻只能有一个写者：一个人在编辑文档，或一个 AI 在做任务。发给 AI 之前（点发送时）所有人和所有文档都必须不在编辑态，且没有未完成的 AI 任务；否则发送不出去并弹出说明。别人可以打开同一工程，只能只读预览。见 [11-设计稿-3](./11-设计稿-3-Git与文档同步.md)、[11-设计稿-4](./11-设计稿-4-综合与待拍板.md)_

- [x] **C5** 点发送时「保存一版」会不会把那句话发出去？未记入版本要不要拦？  
  - 结论：_不发出。提示里的「保存一版」只记版并退出编辑，人再点一次发送。已保存但未记入版本也拦，文案与「还在编辑」分开。见 [12](./12-实现前决策.md)_
