# 手机 OEM 内置 App 产品经理场景设计（已拍板草案）

> 状态：实现依据 · 2026-08-15 按客户端方案修订落盘  
> 运行形态见 [00](./00-产品重定位.md)、[07](./07-客户端架构.md)。异议可在 [03-待确认问题.md](./03-待确认问题.md) 回改。

## 1. 用户画像

两个角色，**同一套 Web**，靠账号和 ACL 区分（见 [00](./00-产品重定位.md) §2）：

**产品设计 / 产品经理：** 在架构师配好的环境里写 PRD、追问、看 Agent 进度。不配 Claude、不选代码仓。

**架构师：** 装的是本机服务器；在浏览器里挂文档根和代码根、复用 Claude/MCP，必要时自己也写技术方案。

产品设计侧特征：

- 需求大多是 **对现有工程的增强**，不是从零新建产品  
- 一个 feature 常 **跨多个代码仓**（如：系统设置 App + Framework + 厂商服务 SDK）  
- 上线前需要写清：用户场景、机型/系统版本范围、权限、与系统能力耦合、兼容与回滚  
- 常有外部材料：评审纪要、竞品笔记、不规整 Markdown/粘贴稿  
- 需要 AI **补上下文、追问缺口**，而不是只生成空壳模板  

## 2. 核心对象

| 对象 | 含义 |
|------|------|
| 工程 | 一次交付工作：1 个文档根 + 0～N 个代码根 |
| 文档根 | 本机专有目录，可写；墨览只打开这里 |
| 代码根 | 本机代码仓，默认只读；可来自 `~/.claude.json` |
| PRD.md | 该工程主文档（Markdown 真相源），在文档根内 |

**决策 F1（已选）：** 工程必须有文档根。代码根尽量绑；允许暂不绑，持续提醒，且不做代码仓核对。

**决策 F2（已选，2026-08-15 修订）：** **1 个专有文档根（可写）+ N 个代码根（只读）**。文档不再写入某个主仓的 `.designweave/`。

## 3. 文档落盘

```text
<文档根>/                       # 用户选的目录，或 ~/Documents/DesignWeave/<工程名>/
  meta.md                       # YAML：代码根列表、阶段
  PRD.md
  gaps.md
  import/
    original.md
  arch/ …                       # 后续阶段
  qa/ …
  .dw/                          # 可重建索引
```

SQLite：工程索引（id、title、docRoot、codeRoots、updatedAt、phase）+ session。

**决策 F3（已选，2026-08-15 修订）：** 桌面主区用墨览（Vditor IR）。`apps/web` 探针可继续简易预览。

## 4. 产品经理主路径

### 路径 A：从零共创 PRD

1. 选文档根 → 从 `~/.claude.json` 勾选代码根（可跳过）  
2. 填写标题 / 一句话目标  
3. 进入 **引导共创**：AI 每次只问 1～3 个问题（OEM 语境：机型范围、入口、权限、与系统 App 关系、是否依赖云端等）  
4. 产品经理回答 → AI 把结论写入 `PRD.md` 对应章节  
5. 可随时切「缺口追问」补全  
6. 导出即下载/打开 `PRD.md`

### 路径 B：导入 Markdown 再完善

1. 创建需求时粘贴或上传 `.md`（排版可不规整）  
2. 原文备份到 `import/original.md`，同时生成初版 `PRD.md`（尽量保留原文，不强行重排）  
3. AI **阅读导入稿**，产出缺口问题清单，向 PM 逐轮追问  
4. 确认后的内容合并进 `PRD.md`（标注修订来源）

**决策 F4（已选）：** 在线 URL 导入本迭代不做；只支持粘贴与文件上传。URL 记入待办。

**决策 F5（已选）：** 导入后不自动大改结构；先保真，再靠追问补全。可选「帮我规整章节」作为显式动作。

## 5. OEM 语境下 AI 必问维度（内置）

引导/追问默认覆盖（可跳过）：

1. 问题与目标用户（终端用户 / 运营商 / 产线？）  
2. 机型 / Android 版本 / 区域 / 品牌差异  
3. 入口与信息架构（设置项路径、桌面图标、负一屏等）  
4. 权限、隐私、合规（录音、位置、通讯录…）  
5. 依赖的系统能力 / 其他内置 App / 云端服务  
6. 涉及哪些已有工程（主仓与关联仓职责切分）  
7. 兼容、升级、开关与回滚策略  
8. 非目标（明确不做）  
9. 验收标准与埋点/指标  

## 6. 多工程上下文如何喂给 AI

**决策 F6（已选）：**

- Agent 默认 `cwd` = **文档根**  
- 代码根写入 `meta.md`，经 `additionalDirectories` 只读（Read / Glob / Grep）  
- 不自动改代码仓；本迭代不做可行性分析写入业务文件  

## 7. UX（本迭代）

**决策 F7（已选）：** 采用简化版「引导 / 文档 / 追问」三态，隐藏架构/测试 Tab。

| 状态 | 主区 | 侧区 |
|------|------|------|
| 引导共创 | 对话（当前问题） | 文档根 / 代码根、已收集摘要 |
| 文档 | PRD.md 编辑+预览 | 保存 / 规整章节 |
| 追问完善 | 缺口问题 + 回答 | 导入原文入口 |

首屏：继续最近工程；新建（选文档根 + 代码根）；导入 Markdown。

## 8. 本迭代明确不做

- 在线 URL 抓取导入  
- 架构 SR / 测试方案  
- 多人实时协同编辑同一 PRD  
- Docker 主路径  
- 产品设计改 MCP / 密钥 / 代码根  
- 管理 API 暴露给浏览器  
- 局域网小服务器主路径  

## 9. 实现顺序

1. 扫描 `~/.claude.json` 作为代码根候选  
2. 创建工程（文档根 + 代码根）  
3. 导入 Markdown  
4. 引导共创 + session 流（见 07 / 08）  
5. 浏览器工作台：墨览 + 对话侧栏
