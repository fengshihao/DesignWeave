# 手机 OEM 内置 App 产品经理场景设计（已拍板草案）

> 状态：实现依据 · 2026-08-10  
> 作者代理已作默认选择；有异议可在 [03-待确认问题.md](./03-待确认问题.md) 回改。

## 1. 用户画像

**主用户：手机 OEM 厂商内置 App 的产品经理 / 软件设计师。**

特征：

- 需求大多是 **对现有工程的增强**，不是从零新建产品  
- 一个 feature 常 **跨多个代码仓**（如：系统设置 App + Framework + 厂商服务 SDK）  
- 上线前需要写清：用户场景、机型/系统版本范围、权限、与系统能力耦合、兼容与回滚  
- 常有外部材料：评审纪要、竞品笔记、不规整 Markdown/粘贴稿  
- 需要 AI **补上下文、追问缺口**，而不是只生成空壳模板  

## 2. 核心对象

| 对象 | 含义 |
|------|------|
| 工程（Repo） | 服务器本机上的代码目录；可来自 `~/.claude.json` |
| 需求（Requirement） | 一次要交付的功能/变更；挂「主工程」+ 可选「关联工程」 |
| PRD.md | 该需求的主文档（Markdown 真相源） |

**决策 F1（已选）：** 需求必须尽量绑定工程。允许「暂不绑定」进入服务器 `data/inbox/`，但引导完善时会持续提醒绑定，且不做代码仓核对。

**决策 F2（已选）：** 跨多仓时指定 **1 个主工程**（文档落在主仓 `.designweave/`）+ **N 个关联工程**（仅作 AI 只读上下文，路径写入 meta）。

## 3. 文档落盘

```text
# 已绑定主工程
<mainRepo>/.designweave/requirements/REQ-<短id>-<slug>/
  meta.md          # YAML frontmatter + 关联仓列表
  PRD.md           # 主文档
  gaps.md          # AI 追问产生的缺口/待确认（可选同步到 PRD 未决节）
  import/          # 原始导入件备份
    original.md

# 未绑定
<dataDir>/inbox/requirements/REQ-.../
  （同上结构）
```

SQLite：需求索引（id、title、primaryRepo、updatedAt、phase）。

**决策 F3（已选）：** 本迭代 Web 编辑器用「Markdown 文本 + 简易预览」，Vditor 留到下一迭代（见 05），先打通工作流。

## 4. 产品经理主路径

### 路径 A：从零共创 PRD

1. 首页选主工程（`~/.claude.json` 列表 + 手动路径）→ 可选关联工程  
2. 填写需求标题 / 一句话目标  
3. 进入 **引导共创**：AI 每次只问 1～3 个问题（OEM 语境：机型范围、入口、权限、与系统 App 关系、是否依赖云端等）  
4. 产品经理回答 → AI 把结论写入 `PRD.md` 对应章节  
5. 可随时切「缺口追问」补全  
6. 导出即下载/打开 `PRD.md`

### 路径 B：导入 Markdown 再完善

1. 创建需求时粘贴或上传 `.md`（排版可不规整）  
2. 原文备份到 `import/original.md`，同时生成初版 `PRD.md`（尽量保留原文，不强行重排）  
3. AI **阅读导入稿**，产出缺口问题清单，向 PM 逐轮追问  
4. 确认后的内容合并进 `PRD.md`（标注修订来源）

**决策 F4（已选）：** 在线 URL 导入本迭代不做；只支持粘贴与文件上传。URL 记入待办。

**决策 F5（已选）：** 导入后不自动大改结构；先保真，再靠追问补全。可选「帮我规整章节」作为显式动作。

## 5. OEM 语境下 AI 必问维度（内置）

引导/追问默认覆盖（可跳过）：

1. 问题与目标用户（终端用户 / 运营商 / 产线？）  
2. 机型 / Android 版本 / 区域 / 品牌差异  
3. 入口与信息架构（设置项路径、桌面图标、负一屏等）  
4. 权限、隐私、合规（录音、位置、通讯录…）  
5. 依赖的系统能力 / 其他内置 App / 云端服务  
6. 涉及哪些已有工程（主仓与关联仓职责切分）  
7. 兼容、升级、开关与回滚策略  
8. 非目标（明确不做）  
9. 验收标准与埋点/指标  

## 6. 多工程上下文如何喂给 AI

**决策 F6（已选）：**

- Agent 默认 `cwd` = 主工程根  
- `meta.md` 中的 `relatedRepos` 写入 system 提示，并允许 Read/Grep 这些路径（只读）  
- 不自动改关联仓代码；本迭代不做可行性分析写入  

## 7. UX（本迭代）

**决策 F7（已选）：** 采用简化版「引导 / 文档 / 追问」三态，隐藏架构/测试 Tab。

| 状态 | 主区 | 侧区 |
|------|------|------|
| 引导共创 | 对话（当前问题） | 主/关联工程、已收集摘要 |
| 文档 | PRD.md 编辑+预览 | 保存 / 规整章节 |
| 追问完善 | 缺口问题 + 回答 | 导入原文入口 |

首屏：继续最近需求；新建（选工程）；导入 Markdown 创建。

## 8. 本迭代明确不做

- 在线 URL 抓取导入  
- Vditor 集成  
- 架构 SR / 测试方案  
- 多人实时协同编辑同一 PRD  
- Docker 主路径  

## 9. 实现顺序

1. 扫描 `~/.claude.json` 工程列表 API  
2. 需求 vault + 创建绑定（主仓/关联仓）  
3. 导入 Markdown  
4. 引导共创 + 导入后追问（AI，无 Key 时 mock）  
5. 首屏与工作台 UI 可用化
