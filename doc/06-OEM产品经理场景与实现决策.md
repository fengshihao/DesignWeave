# 手机 OEM 内置 App 产品经理场景

> 状态：实现依据 · 2026-08-22 按 [18](./18-工程目录与标准PRD.md) 修订  
> 运行形态见 [00](./00-产品重定位.md)、[07](./07-客户端架构.md)。

## 1. 用户画像

**产品经理：** 在架构师配好的环境里建工程、写标准 PRD 文档包、跟 AI 把文档变清晰、再做可行性。不配 Claude，不选代码路径。

**架构师：** 本机服务器；设运行根目录；从 `~/.claude.json` 批准代码目录；复用 Claude / MCP。

产品侧特征不变：多半是对现有工程的增强；一个 feature 常跨多个代码仓；要写清机型 / 权限 / 兼容；常有外部草稿；需要 AI 追问缺口而不是只吐空模板。

## 2. 核心对象

| 对象 | 含义 |
|------|------|
| 运行根目录 | 架构师设定；下面每个子文件夹一个工程 |
| 工程 | 一次交付：标准 PRD 文档包 + Git |
| 已批准代码目录 | 服务级、只读；与工程脱钩；AI 自己选用 |
| 文档包 | 单文件 `PRD.md` + meta；AI 维护 gaps / 调研，见 [18](./18-工程目录与标准PRD.md) §3 |

**F1：** 工程必须有文件夹。没有已批准代码目录也能建，可行性不可用。  
**F2：** 文档不写进业务仓 `.designweave/`。  
**F3：** 主区用墨览。

## 3. 两条路径

**F4：** 不做 URL 导入，只粘贴 / 上传。

**路径 A 模板：** 人把每一项填完 → AI 检查清晰度 → 再进入共创 / 拷问 / 可行性。

**路径 B 导入：** 原文进 `import/original.md` → 立刻拆进 `PRD.md` 各 `##` 节 → 缺失进 `gaps.md` → 对话里补齐。

**F5（2026-08-22 改口）：** 导入即生成标准包，不再先保真不重排。

## 4. OEM 必问维度

引导 / 追问 / 清晰度检查默认覆盖（可跳过）：

1. 问题与目标用户（终端用户 / 运营商 / 产线）
2. 机型 / Android 版本 / 区域 / 品牌差异
3. 入口与信息架构
4. 权限、隐私、合规
5. 依赖的系统能力 / 其他内置 App / 云端
6. 可能涉及哪些已有实现（由 AI 对已批准目录识别，不问产品经理选仓）
7. 兼容、升级、开关与回滚
8. 非目标
9. 验收与埋点

## 5. 多仓怎么喂给 AI

**F6（2026-08-22 改口）：**

- Agent `cwd` = 当前工程文件夹
- 本轮选用的已批准目录经 `additionalDirectories` 只读
- 不改业务代码
- 选用理由写进 `调研.md`
