# Git 与文档同步

> 仍有效：保存 ≠ 记入版本、一人编辑权、人 XOR AI。产品壳与工程模型听 [18](./18-工程目录与标准PRD.md)。  
> 2026-08-16 修订：同一时刻只能有一个写者。别人可进只读预览。

---

## 结论（默认策略，拍板级）

**名字：人写和 AI 写错开；编辑权一人；即时落盘，人记人的版，AI 一轮一版。**

1. **同一时刻只有一个写者。** 要么是**一个人**在编辑文档，要么是**一个 AI** 在做任务，二者不能同时，也不能两个 AI、两个人一起写。发给 AI 之前（点发送时检查）：所有人、所有文档都不在编辑态，且没有未完成的 AI 任务。否则发送不出去，弹出说明。
2. **一个工程同时只有一个人能编辑。** 别人可以打开，但只能只读预览（看文档、看 AI 进度），不能改、不能开任务。本阶段不做多人同时改、不做实时双光标、不做「留我的 / 用新的 / 看差异」。
3. **磁盘是纸面。** 人 Cmd+S、AI 往文档仓写、从远端拉下来，都先落到磁盘。预览的人和 AI 进行中的只读墨览都跟上磁盘，不会和未保存修改打架。
4. **版本是刻意留下的刻痕。** 界面不说 commit / HEAD。人的刻痕来自按钮「记入版本」（用户口中的「保存一版」）。AI 的刻痕来自**一轮成功结束时自动记一版**（作者显示为 AI）。点发送时若还在编辑态，先拦住，人保存一版并退出编辑后再发。
5. **进行中不记版。** 长任务写到一半的章节可以马上在只读墨览里看，时间线不出现半成品版。
6. **第一版只用主线。** 不开分支。远端可选，默认不自动推。
7. **不设「采纳才允许写盘」。** 否决 AI 用「撤销这一版」，不是事先拦写盘。

这一条取代「脏文档三选一」「边写边跑的交叉时序」「两人同时改同一篇」。

---

## 理由

产品经理要的是：AI 刚写完能立刻看见；事后能指出哪次是 AI、哪次是我；能回到改之前。他们不要处理「我和 AI 同时改同一段」。

错开写盘之后，三选一、etag 打架、交叉时序都可以不做。开 AI 前先保存一版，时间线上「我改之前」永远是干净的一刀；AI 写的时候人只读，写完自动记 AI 的一版，再放手去改。

若每次 Cmd+S 都记一版，时间线会被灌满。若 AI 只写盘不记版，人一改就和 AI 糊在一起。所以仍然：盘随时写；人的版靠按钮；AI 的版卡在「一轮成功结束」。侧栏结束卡片提供「对比上一版 / 撤销这一版」。

## 用户词汇（界面只用这些）

| 用户看到的 | 意思 |
|------------|------|
| 保存 | 把墨览里的字写到文档仓。快捷键 Cmd+S |
| 未保存 | 墨览里的字还没写到磁盘 |
| 记入版本 | 把磁盘上相对「已记下的最新一版」多出来的改动刻进时间线 |
| 未记入版本 | 磁盘已保存，但比时间线最新一版还多改动 |
| 版本时间线 | 每一次刻痕：谁、何时、一句说明 |
| 对比 | 看两版（或「当前纸面 vs 某一版」）差在哪 |
| 打开这一版 | 墨览只读看旧纸面 |
| 恢复这一篇 | 把**当前这篇**换成某一旧版的内容（先记或不记，见下） |
| 撤销这一版 | 把时间线最新的 AI 一版退掉，磁盘回到它之前（二次确认） |
| 保存一版 | 与「记入版本」是同一件事，拦 AI 开任务时用这句 |
| 同步到远端 / 从远端更新 | 可选；架构师先挂好远端 |
| 预览 | 工程里有别人在编辑（或持有编辑权）。自己只能看，不能改 |
| 有人在编辑 | 列表和顶栏提示谁持有编辑权；自己仍可打开做预览 |

禁止在产品经理界面出现：commit、push、detached、stash、working tree、冲突标记 `<<<<<`、etag。拦住时只用人话：先保存一版并退出编辑再发，或等 AI 写完，或你现在是预览。

## 同一时刻只有一个写者

产品规则就这一句：

> 同时只能有一个 AI 实例，或一个人，在做调研或在编辑文档。

发给 AI 之前必须同时满足：

- 没有任何一篇文档处于编辑态（没有人正在改字、没有未保存的编辑）
- 没有任何一个人处于编辑态（预览可以）
- 没有未完成的 AI 任务（同一工程同时只跑一个 AI）

**关卡就是发送按钮。** 不满足时点发送：消息不发出去，弹出提示。不要悄悄开跑。

| 点发送时的情况 | 弹出 |
|----------------|------|
| 自己还在编辑，或还有文档未保存 / 未退出编辑态 | 「还有文档在编辑。请先保存一版并退出编辑，再发给 AI。」 |
| 别人正在编辑（自己是预览） | 「李敏正在编辑文档，你现在是预览，不能发给 AI。」 |
| 这个工程里 AI 还有任务没做完 | 「AI 还有任务没做完，现在不能再发。请等它写完，或取消本轮。」 |

自己还在编辑时，提示里可以带 **[ 保存一版 ]**：先把所有改动记入版本并退出编辑态。保存完后**不自动发出刚才那句**，人再点一次发送——避免「我只是想存一下却把半句话发给 AI」。

**反过来：AI 在跑时，谁都不能进编辑态。** 点墨览改字、导入、恢复、记入版本，同样弹出，不写入：

```text
AI 正在写文档，现在不能改。
请等它写完，或取消本轮后再改。

[ 等它写完 ]
[ 取消本轮 ]
```

「取消本轮」后才允许进入编辑。预览的人不能取消别人的任务，只看到：「AI 正在写文档，你现在是预览。」

工作台三栏都在。预览的人：只读跟上文档和 AI 进度；不能改、不能发、不能取消。

**AI 一轮结束（成功 / 失败 / 取消）**  
没有进行中的任务了。持有编辑权的人可以进入编辑态，顶栏「可以改了」。预览的人仍是预览。成功结束的那一版已在时间线上。

同一工程同时只允许一个 AI 实例：上一轮没结束，发送一律拦住。

## 编辑权（别人可进，只能预览）

第一版假设：**不会多人对同一个工程同时改。** 锁的是编辑权，不是进门。

```text
工作台
 ├─ 持有编辑权：可改 / 可开 AI（仍遵守人 XOR AI）
 └─ 其他人：只读预览（文档 + AI 进度都跟着看）
```

| 用户做什么 | 系统做什么 | 反馈 |
|------------|------------|------|
| 打开一个没人持有编辑权的工程 | 编辑权给当前用户，进入可写工作台 | 正常进入，可改 |
| 打开一个别人已持有编辑权的工程 | **允许进入**，墨览只读预览 | 顶栏：「李敏正在编辑，你现在是预览。」列表同样标明 |
| 预览时点改字 / 导入 / 记入版本 / 开 AI / 取消本轮 | 拦住，不写盘 | 「李敏正在这个工程里，你现在是预览，不能改。」 |
| 预览时看文件、打开篇章、看时间线、对比 | 允许，只读跟上磁盘 | 和 AI 进行中的只读同一套跟随 |
| 持有者回到工程列表 / 退出登录 | 立刻释放编辑权 | 预览的人顶栏变为「可以开始编辑」；谁先点「开始编辑」谁拿到 |
| 持有者关掉浏览器，但 AI 还在跑 | **不释放编辑权**（任务还在，锁跟着人） | 本人点「回到工程」以持有者身份接上（墨览仍只读直到 AI 写完）。别人继续预览，可看进度，仍不能改 |
| 持有者关掉浏览器，且没有进行中的 AI | 约 2 分钟后释放编辑权 | 仍在预览的人看到「可以开始编辑」 |
| 编辑权坏了（人走了却一直占着） | 架构师「解除编辑权」 | 原持有者若还在，变成预览并提示「编辑权已解除」；产品经理没有这个按钮 |

自己已持有编辑权时，从另一台电脑 / 另一个浏览器再打开：第二处按预览进。人话：「你在另一处正在编辑，这里是预览。」不做抢锁。

预览不是第二个编辑台。磁盘变化一律换成新内容（预览没有未保存修改）。

## 何时记入版本

### 人

| 用户做什么 | 系统做什么 | 反馈 |
|------------|------------|------|
| Cmd+S / 「保存」 | 只写当前篇到磁盘 | 「已保存」。若相对时间线仍有多出的改动，顶栏保持「未记入版本」 |
| 点「记入版本」 | 列出将纳入的文件（默认：磁盘上所有相对最新版有改动的文档，可取消勾选）→ 预填说明「我：保存 PRD.md」等，可改 → 确认后刻一版，作者=当前登录名 | 「已记入版本」。顶栏清掉未记入 |
| 关工程或退出时仍有未保存 | 先拦：保存 / 放弃编辑 / 留下等下次（磁盘仍是旧的，浏览器会话可丢） | 人话，不丢盘上已保存的 |
| 关工程时已保存但未记入版本 | 提醒可记入，允许「以后再说」 | 不强制，以免把每次离开都变成仪式 |

**Cmd+S 绝不自动记版。** 记入版本可用 Cmd+Shift+S。

### AI

| 时机 | 系统做什么 |
|------|------------|
| 一轮进行中写文件 | 只写磁盘，发「文件已变」。不记版。此时人只读，墨览跟上 |
| 一轮成功结束 | **自动记一版**，作者=AI，说明如「AI：写入调研.md 并补 PRD 可行性」。然后允许进入编辑台 |
| 一轮失败 / 被取消 | 不自动记版。已写到磁盘的留着。右侧说明：「这一轮没有记入版本。已经写到纸面上的内容还在，可以改完后自己点记入版本，或从时间线恢复到上一版。」然后允许进入编辑台 |

一轮 = 右侧一次「跑完」的任务，不是每一句工具调用。

### 提交说明

- 自动生成，人可在记入前改（人的版）；AI 的版记入后可在时间线「改说明」（P1；P0 可只读说明）。
- 格式：`我：…` / `AI：…` / `张三：…`。不要把工具名写进说明。

## 时间线、打开旧版、对比、恢复

时间线从顶栏「版本」打开，覆盖在工作台之上，不另做网站后台页。

```text
┌ 版本时间线 · 设置页夜间模式 ──────────────┐
│  · 今天 16:02  AI：写入调研.md…     [打开] [对比] [撤销] │
│  · 今天 15:40  我：保存 PRD.md      [打开] [对比] [恢复] │
│  · 昨天 11:12  李敏：导入原稿        …                   │
└──────────────────────────────────────────┘
```

**打开这一版：** 墨览整栏换成该版该篇的正文，**只读**。顶条：「这是 今天 15:40 的版本（我）。[恢复这一篇到纸面] [与当前对比] [返回编辑]。」左栏文件仍是当前磁盘树；切文件则打开该文件在这一版的内容（若该版还没有此文件，说「这一版里还没有这篇」）。

**对比：** 默认「当前纸面 vs 选中的一版」。也可在时间线勾两版。中栏上下或左右出差异，第一版做「整段红绿」即可，不做 IDE 式行内接受/拒绝。对比时不可编辑；要改，先回到编辑再动手。

**恢复这一篇：** 只动当前打开的这一文件，把它变成旧版内容并写盘。恢复后顶栏「未记入版本」，人再决定是否记一版。不要静默记一版，以免「我只是想看看再改」变成历史噪音。

**撤销这一版：** 仅对时间线**最新**且作者为 AI 的一版提供主按钮（人的最新一版用「恢复」）。AI 还在跑时不能撤销。二次确认：「撤销后，这一版里改过的文件会回到上一版的样子。」撤销本身再记一版，说明「我：撤销 AI 的某某版」，以便还能反悔。必须在编辑台里做（因此当时没有进行中的 AI）。

**整仓回到某一版：** 藏在时间线菜单里，二次确认并要求打字确认工程名。P0 可以先做「单篇恢复 + 撤销最新 AI 版」；整仓回退若来不及，标 P1，但菜单要留位以免开发做成唯一回退方式。

## 文件一变，浏览器怎么跟

因为人改和 AI 写不会叠在同一时刻，跟随规则只剩一条：

**只读时（含 AI 进行中）：磁盘变了就换成新内容，文件树立刻跟上。** 不要整页刷新。AI 新建 `调研.md` 时树里带「新」标记，直到人点开过一次。正在写的文件用安静圆点，不要闪。

编辑台里没有「别人或 AI 同时改这篇」这件事。旁路（有人用别的编辑器改同一目录）本阶段不管；若发生了，下次打开或只读跟上即可，不做三选一。

## 分支、远端

**分支：** 第一版只用主线（`main` 或已存在的默认主线）。界面不出现建分支。文档目录若已是版本库且不在主线：新建时拦住并说人话。

**远端：** 架构师在新建工程或工程设置里可选关联。产品经理 P0 可以**没有**推送按钮。P1 再给「同步到远端」。栏位在新建向导里就要有。多人同时改靠编辑权拦掉，不靠远端合并。预览的人不能从远端更新。

从远端更新（P1）：必须在编辑台、没有进行中的 AI、且没有未保存/未记入。否则说「先保存一版（或等 AI 写完）再从远端更新。」若干净则拉取并跟上。远端和主线对不上：失败并说「远端和本机文档对不上，请让架构师处理。」

**新建时如何变成版本库：**

| 目录状态 | 默认 | 人可以 |
|----------|------|--------|
| 空 / 不是版本库 | 勾选「初始化为文档版本库」 | 取消则**不允许**创建（文档仓必须是版本库，这是产品一句话锁死的）。若技术上要允许，也只能是开发期后门，产品不提供 |
| 已是版本库且在主线 | 直接用 | 显示最近一版说明 |
| 已是版本库且不在主线 | 不允许 | 换目录或回到主线后再选 |

初始化时写入一份忽略名单（索引缓存、系统垃圾文件），不要把可重建的运行态推进时间线。第一版自动记一版「AI/系统：初始化文档仓」，作者可以显示为「系统」，避免和后来的 AI 调研混在一起。

## 信任与 Git 作者怎么对上号

- 时间线作者：`AI` / `系统` / 登录显示名。AI 不借用架构师的名字。
- 右侧信任条在可行性期间与结束后都在：「AI 只读了：设置 App、Framework。没有改任何代码仓。」
- 打开 AI 那一版时，只读条重复一句：「这一版由 AI 写入文档仓。」
- 代码仓更新后的「按最新代码再调研」是架构师工程设置里的动作（P1）；产品经理只看到新的一轮可行性。

## 失败时说什么（产品经理能懂）

| 情况 | 说 |
|------|----|
| Claude 没登录 | 这台工作台还不能找 AI。请让架构师完成本机 Claude 登录。 |
| 代码仓路径没了 | 工程挂的代码仓找不到了（路径可对架构师显示）。可行性暂停；若当前在编辑台仍可改文档。 |
| 点发送时还有人/文档在编辑 | 还有文档在编辑。请先保存一版并退出编辑，再发给 AI。 |
| 点发送时 AI 还没跑完 | AI 还有任务没做完，现在不能再发。请等它写完，或取消本轮。 |
| 想改但 AI 还在写 | AI 正在写文档，现在不能改。请等它写完，或取消本轮后再改。 |
| 预览时点发送或点编辑 | 李敏正在编辑文档，你现在是预览，不能改、不能发给 AI。 |
| 工程有人在编辑 | 李敏正在这个工程里，你现在是预览，不能改。 |
| 工程已在另一处编辑 | 你在另一处正在编辑，这里是预览。 |
| 记入版本失败 | 纸面上的字还在。版本没记下，请稍后再试；若反复出现请让架构师看文档仓权限。 |
| 没有权限 | 需要架构师权限才能改环境和代码仓。 |
| 远端对不上 | 远端和本机文档对不上，请让架构师处理。你的纸面没丢。 |
| 撤销失败 | 这一版没能撤销，当前纸面没变。 |

## 附录（给拆任务的人，不是产品正文）

交互协议已拍板的部分沿用客户端架构：打开/保存走文件读写；磁盘变化用工程内文件已变通知（只读跟上即可）；长任务用会话编号，连接断开不等于取消。Git 只作用在文档根。代码根只读，不在本文的版本时间线里。工程锁与「编辑台 XOR AI」是产品规则：锁的是编辑权，别人仍可只读预览。不要再实现脏文档三选一。

本附录不规定 URL。Git 版本与只读跟随磁盘已经是现行约束，见 [12](./12-实现前决策.md)、[18](./18-工程目录与标准PRD.md)。

## 本稿自批：3 个漏洞

1. **关浏览器后的 2 分钟**只释放编辑权，预览的人已经在里面。超时后若两人同时点「开始编辑」，谁先到谁拿到，另一个留在预览并提示「李敏刚刚开始编辑」。
2. **点发送被拦住后，提示里的「保存一版」不要顺便把那句话发出去。** 存完退出编辑，人再点一次发送，意图才清楚。
3. **架构师「解除编辑权」**不要把人踢出工程，只降成预览，并说清「你现在是预览」。

产品壳与工程模型的后续改动写在 [18](./18-工程目录与标准PRD.md)，不要再开第 4 稿。
