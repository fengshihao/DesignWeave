## 需要你拍板的问题

### D1. 是否继续 full ESM（步骤 3b/3c）？

**现状**：编辑器仍是 4346 行 IIFE，只是真源搬到了 `packages/molan-core/src/`。

**选项**
- **A（推荐渐进）**：维持 IIFE + sync，先把 host/protocol 跑稳；3b 按模块逐个拆，每模块一条 Playwright
- **B（激进）**：一步到位 ESM + bundler 加载 Vditor，省 sync 但 D2 风险高

**我的倾向**：A。拷贝漂移问题已被「真源 → dist → sync」消除，不必为 ESM 本身而 ESM。

---

### D2. Vditor UMD 加载策略

**风险**：`method.min.js` / `index.min.js` 是 UMD，Next.js / VS Code webview / Vite 上 `import()` 行为未在本仓库验证。

**回退方案（文档 D2）**：保留动态 `<script>` 注入，路径由 `molan-core` 统一管理，三端不再各自 sync vendor。

**待决**：是否接受回退方案作为长期方案，还是必须 ESM 化？

---

### D3. Web 工作台 iframe 是否保留？

**已拍板（2026-08-20）**：Web 工作台采用 **方案 A — inline 同页挂载，保留 reader-header**。

- `MolanFrame` 不再使用 iframe / `host.html`
- 通过 `mountInlineHost` + `renderInlineShell` 在同页渲染完整编辑器壳
- 主题切换直接作用于 `document.documentElement`（与工作台 `globals.css` 统一）
- VS Code / 浏览器工作室 **不变**，仍用各自 webview / index.html 顶栏
