## 结论

技术人员把一台机器配成工作台之后，产品经理只做这件事：**打开已有工程，把「对照代码做调研、补 PRD」托付给 AI，自己在墨览里改到能拿去评审。** 人写的和 AI 写的都留在文档仓的版本时间线上。

界面锁死为三栏工作台（文档树 · 墨览 · AI 档位）。**同一时刻只有一个写者**：要么一个人在改文档，要么一个 AI 在跑任务。点发送给 AI 之前，所有人和所有文档都必须不在编辑态，且没有未完成的 AI 任务；否则发送不出去，弹出说明。**一个工程同时只一个人能编辑**，别人可以打开但只能只读预览。Git：人点「记入版本」；AI 一轮成功结束自动记一版。第一版主线到底，不改业务代码。

本阶段 P0 验收：

> 产品经理打开已有工程 → 托付一次可行性调研（期间只能看、不能改）→ 写完后改一版 PRD → 能分清 AI 写的和我写的，并能回到其中任意一版；调研过程中已落下的章节当时就能在只读墨览里看见。别人可进同一工程只读预览，不能改。

---

## 理由

探针首页像后台、对话占满连接、没有文件跟随、没有文档版本——那是技术探测，不是产品。旧 UX 讨论把引导做成主区问答、把架构/测试 Tab 灰着占位，会让第一眼继续不知道下一步。已拍板的安装形态、角色 ACL、墨览写回、会话与连接分离、对话在侧栏，都不动。

缺的是把「托付 + 版本」收成同一条主路径，并**用互斥和工程锁把同步做薄**。前三稿分别补了为什么、房子长什么样、版本规则。2026-08-16 把「脏文档三选一 / 双人同时改」从推荐设计里拿掉。

## 当前推荐产品设计

### 1. 给谁、不给谁

- **主用户是产品经理。** 不看仓库、不配模型、不碰 MCP 和密钥。
- **架构师配环境、建账号、挂文档仓和只读代码仓。** 自己也可以进同一套工作台写技术方案。
- 不是笔记库、不是 ChatGPT 壳、不是工程师 IDE。不做 Tauri 工作台、公网 SaaS、实时双光标。让 AI 改业务代码是以后单独开的门。

### 2. 页面与权限

```text
登录 → 产品经理：工程列表（继续上次 / 进行中任务）
     → 架构师：同上 + 新建工程 / 用户 / 设置

工程工作台（唯一主界面）
  左  文档仓文件树、导入
  中  墨览（历史版时只读）
  右  共创 | 拷问 | 可行性
附属  版本时间线、对比、工程设置（仅架构师）

本阶段隐藏：技术方案 / SR / 测试
```

产品经理没有新建工程、没有选文件夹、没有设置。空列表时请他找架构师，不放演示模式。

### 3. 主路径（逐步）

1. 架构师：安装启动 → 第一个账号 → 确认 Claude 可用（MCP 默认全开）→ 建产品经理账号 → 新建工程（文档目录初始化为主线版本库，可选远端栏位，勾选代码仓）。
2. 产品经理：登录 → 打开工程 → 若无人持有编辑权则自己可改；若有人在编辑则只读预览。三栏，默认上次的文档与档位。
3. 切到可行性（无代码仓则锁定并说明原因）→ 用中文托付。点发送时若有人/文档仍在编辑，或 AI 还没跑完：弹出说明，不发出。信任条写明只读哪些仓、未改代码。
4. 进行中墨览只读；可关浏览器，持有编辑权的人再进工程即接上。已写到磁盘的章节立刻可在只读墨览打开。取消是右侧明确按钮。别人可进同一工程预览进度，不能改、不能取消。
5. 一轮成功：自动记一版，作者 AI；持有编辑权的人墨览恢复可改，预览的人仍是预览。人改 PRD，Cmd+S 只保存；点「记入版本」留下自己的刻痕。
6. 时间线对比「AI 刚写完」和「我改之前」；不妥就撤销最新 AI 版，或单篇恢复到某一版。

导入：粘贴或上传，原文进 `import/original.md`，PRD 先保真。规整章节是显式动作（P1）。

### 4. Git 与同步（默认策略，不再并列）

详见 [11-设计稿-3](./11-设计稿-3-Git与文档同步.md)，此处只锁规则：

| 规则 | 内容 |
|------|------|
| 同一时刻一个写者 | 要么一个人改文档，要么一个 AI 跑任务。点发送时检查：所有人、所有文档不在编辑态，且没有未完成的 AI 任务；否则弹出说明，消息不发出 |
| 工程锁 | 一人持有编辑权；别人可进只读预览。持有者关浏览器且 AI 还在跑则编辑权不放；无任务则约 2 分钟后放。架构师可解除编辑权（对方变成预览） |
| 保存 | Cmd+S 只写磁盘，不记版 |
| 人的版本 | 「记入版本」。点发送时若还在编辑态，先拦住；人保存一版并退出编辑后再发 |
| AI 的版本 | 一轮**成功结束**自动记一版；进行中、失败、取消都不自动记 |
| 文件跟随 | 只读时磁盘变了就换成新内容；不做脏文档三选一 |
| 文件树 | 增删改名立刻变 |
| 分支 | 只用主线 |
| 远端 | 向导里留栏；P0 可不推送 |
| 回退 P0 | 打开旧版只读、两版对比、恢复当前篇、**撤销最新 AI 版**（须在编辑台、AI 没在跑） |
| 回退 P1 | 整仓回到某一版 |

工程列表和工作台顶栏都要能看见「未记入版本」，避免磁盘已变、时间线未变时以为没人改过。

### 5. 长任务

关浏览器 ≠ 取消。会话挂在工程上，产品经理不记编号。工程卡片、顶栏红点、右侧状态说的是同一轮。部分落盘在只读墨览里跟上（持有者和预览者都跟上）。失败用人话，已写文档保留，并重申没改代码仓。AI 在跑时不释放编辑权，以便本人回来接着看；别人继续预览。

### 6. 信任

右侧顶栏常驻，不随消息滚走。时间线里 AI 不借用任何人的登录名。可行性结论写进文档仓，不写进代码仓。密钥和 MCP 开关产品经理看不见，接口上也进不去。

### 7. 优先级（实现仍须等人说开始）

**P0**（内部可日用的「托付 + 版本 + 跟随」）

- 登录与角色 ACL；架构师配环境；产品经理只进已有工程
- 三栏工作台；墨览保存写回；导入先保真
- 三档 AI；可行性只读代码仓、只写文档仓；中文进度；会话可离开可取消
- **同一时刻一个写者**（发送前所有人、所有文档不在编辑态，且没有未完成 AI）；编辑权一人，别人只读预览
- 文档仓必须是版本库；保存 ≠ 记入版本；开 AI 前先保存一版；AI 一轮一版；时间线 / 对比 / 打开旧版 / 恢复单篇 / 撤销最新 AI 版
- 只读时文件跟随；文件树跟随（不做脏文档三选一）
- 信任条与失败人话

**P1**

- 远端推送/拉取、改 AI 说明、缺口与章节锚点写回、规整章节、按最新代码再调研、整仓回退、编辑权超时与架构师解除的打磨

**以后**

- 拆 SR 与测试、开门改业务代码、安装包与邀请视觉、实时双光标、Wiki/Notion、URL 导入、文档分支

相对 [09 §3](./09-云端迭代入口.md) 原先的第一刀：把 **「文档 Git 版本」和「打开文档在只读时跟随磁盘」收进 P0**，同步策略按互斥 + 工程锁做薄。安装包打磨、产品设计邀请流、拆 SR、改业务代码、公网、实时协同、脏文档三选一，仍不做。09 的验收列表已按本稿 P0 回写。未听到「开始写代码」之前，不要改 `apps/`。

## 8 问已锁定（见 [12](./12-实现前决策.md)）

不再并列「倾向」。人改口先改 12 和 03。

1. **AI 一轮成功是否自动记入版本？**  
   **是。** 进行中不记；失败/取消不记。开 AI 前已要求先保存一版，故结束时不会再和人的未保存打架。

2. **人的 Cmd+S 是否同时记版？**  
   **否。** 记入版本是单独动作。点发送被拦住时，提示里的「保存一版」只记版并退出编辑，**不**把那句话发给 AI。

3. **P0 要不要做远端推送？**  
   **不要。** 新建工程留「关联远端」栏给架构师；产品经理的「同步到远端」放 P1。

4. **第一版要不要文档分支？**  
   **不要，只用主线。**

5. **缺口用单文件 `gaps.md` 还是一缺口一文件？**  
   **单文件 `gaps.md`。**

6. **误操作时 P0 的最大回退出口？**  
   **撤销最新 AI 版 + 单篇恢复。** 整仓回退放 P1。

7. **两个产品经理改同一篇？**  
   **不同时改。** 一人持有编辑权；别人可打开只读预览。不实时协同、不三选一、不双光标。

8. **引导共创时主区是对话还是墨览？**  
   **永远墨览，对话在右侧。** AI 进行中主区仍是墨览，只是只读。

## 本稿自批：3 个漏洞（同步已按审稿简化）

1. **关浏览器后的编辑权。** 无任务约 2 分钟释放、有任务不释放。预览的人已经在里面，超时后点「开始编辑」即可，不会「进不去」。
2. **「撤销再记一版」产品经理仍可能晕。** 倾向仍先保留可反悔。
3. **架构师误选代码仓当文档根。** 初始化时若目录里大量非 md 源码，警告「这看起来像代码仓」。仍作实现校验，不另开一问。
