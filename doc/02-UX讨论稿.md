# UX 讨论稿

> 状态：与第 4 稿对齐 · 2026-08-16 同步简化（人 XOR AI、编辑权一人可预览）  
> 说明：当前 `apps/web` 仅是技术探针，**不作为交互定稿**。产品设计以 [11-设计稿-4-综合与待拍板.md](./11-设计稿-4-综合与待拍板.md) 为准。线框与 Git/同步细节见 [第 2 稿](./11-设计稿-2-信息架构与主路径.md)、[第 3 稿](./11-设计稿-3-Git与文档同步.md)。

## 1. 当前实现的问题（共识）

- 首页「新建 + 列表」偏网站后台，不像本机工作台
- 设计页双栏、JSON、多种聊天模式，**第一眼不知道下一步做什么**
- 架构 / 测试 Tab 灰显占位，增加噪音（本阶段应隐藏，不是灰着）
- 「演示模式」与真实 Claude 能力边界不清晰
- 缺少「我在哪个工程里做需求」的强提示
- 关掉浏览器任务就停；磁盘上的文档变了，页面不知道

## 2. 产品心智

一句话：

> **架构师配好环境之后，产品经理打开工程 → 把对照代码的调研和补 PRD 托付给 AI → 人在墨览里改 Markdown。同一时刻只有一个写者；别人可进只读预览。人写的和 AI 写的都记入文档版本。**

主对象不是 Chat，而是 **工程**。文档在专有文档仓里。对话是右侧手段，文档是中间结果。

```text
本机工作台
└── 工程 A（文档仓 · 可写 · 版本库）+ 若干只读代码仓
    ├── PRD.md
    ├── 调研.md / gaps.md
    ├── 技术方案 / SR（以后，入口先藏）
    └── 测试方案（以后，入口先藏）
└── 工程 B
```

## 3. 信息架构（与第 4 稿一致）

### 3.1 首屏

**架构师：** 登录后可见设置（MCP 全开可关、浏览服务器目录挂根、用户）、继续最近工程、新建工程。

**产品设计：** 登录后只有「继续最近工程 / 打开已有工程」。没有设置、没有选文件夹、没有新建。有进行中的长任务要写在工程卡片上；别人正在编辑的工程标「谁在编辑 · 可预览」，点进去只读。

顶栏固定显示：工程名、当前文档、保存状态、是否未记入版本。产品设计默认不强调本机绝对路径。

### 3.2 工作台：固定三栏，右侧换档

不要「主区随步骤变成问答」。房子始终是：

| 栏 | 职责 |
|----|------|
| 左 | 文档仓文件树与导入（不列代码仓） |
| 中 | 墨览。编辑台时可写；AI 进行中或历史版本时只读 |
| 右 | AI 档位：共创 / 拷问 / 可行性，互斥切换 |

| 档位 | 右侧 | 墨览 |
|------|------|------|
| 共创 | 每次 1～3 问（OEM 维度见 06，问题在侧栏） | 打开 PRD，写到的章节可滚到眼前 |
| 拷问 | 缺口列表，答完写回 | 点缺口高亮对应标题 |
| 可行性 | 中文进度；结论写入 `调研.md` / PRD 可行性节 | 进行中只读打开已落下的篇 |

未挂代码仓：可行性锁定，共创和拷问仍可用。架构 / 测试本阶段隐藏。

原则：

- **默认不露出 JSON**
- **聊天不是首页**，也不是引导阶段的主区
- 一次只强调一个主行动（回答下一问 / 处理缺口 / 开始调研 / 保存或记入版本）
- **人改和 AI 写不同时**：编辑时不能开任务，任务中不能改
- AI 一轮结束的「本轮写了哪些文件 + 对比 / 撤销」：磁盘即时写，版本按第 3 稿规则记

### 3.3 架构 / 测试阶段（以后）

- 同一工程下再露出技术方案、SR、测试方案
- 未解锁不占灰 Tab
- 对照代码需要已绑代码根

## 4. 关键交互原则

1. **工程上下文永远可见**
2. **一次只强调一个主行动**
3. **对话是侧栏，文档是结果**
4. **保存 ≠ 记入版本**（Cmd+S 只写盘；人点记入版本；开 AI 前若有未记入须先「保存一版」；AI 一轮成功自动记一版）
5. **同一时刻一个写者**：发给 AI 前所有人、所有文档不在编辑态，且没有未完成的 AI 任务。点发送不满足就弹出说明、不发出。别人可进只读预览。
6. **中文优先**，专有词保留 PRD / SR
7. **失败可理解**：Claude 未登录、代码仓路径没了、版本没记下、权限不够、工程被占用，都用人话
8. **信任可见**：AI 只读了哪些代码仓、没有改业务代码；时间线里 AI 不借用登录名
