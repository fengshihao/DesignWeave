# UX 讨论稿

> 状态：待共创 · 2026-08-09  
> 说明：当前 Web UI 仅是技术探针，**不作为交互定稿**。本节用于对齐信息架构与主路径。

## 1. 当前实现的问题（共识候选）

- 首页「新建 + 列表」偏网站后台，不像本机工作台  
- 设计页双栏：章节树 + JSON 编辑 + 聊天模式过多，**第一眼不知道下一步做什么**  
- 架构 / 测试 Tab 灰显占位，增加噪音  
- 「演示模式」与真实 Claude 能力边界不清晰  
- 缺少「我在哪个工程里做需求」的强提示  

## 2. 建议的产品心智

一句话：

> **选一个本地工程 → 把需求说清楚（PRD）→ 再往下交给架构 / 测试。**

主对象不是「Chat」，而是 **需求工作项（Requirement）**，挂在工程下。

```text
本机工作台
└── 工程 A
    ├── 需求 R1（进行中 · 设计）
    ├── 需求 R2（已出 SR）
    └── 需求 R3（测试中）
└── 工程 B
    └── ...
```

## 3. 信息架构草案（V2）

### 3.1 首屏（浏览器打开小服务器后）

只做三件事：

1. 登录（口令/简单账号）后，显示服务器 Claude 配置状态  
2. **继续最近需求**  
3. **从服务器工程新建需求**（浏览的是服务器目录，不是自己电脑）  

顶栏固定显示：当前服务器名/地址（避免人不知道连的是哪台机）。

不做：复杂仪表盘、多阶段灰 Tab、把安装向导塞进日常首屏。

### 3.2 需求工作台（设计阶段主界面）

建议从「双栏编辑器」改为 **三态工作流**（同一屏，但主区随步骤切换）：

| 步骤 | 用户目标 | 主区 | 侧区 |
|------|----------|------|------|
| 1 收集 | 把想法说全 | 引导式问答（每次 1～3 问） | 工程信息 / 已收集要点 |
| 2 成文 | 得到可读 PRD | 文档预览（Markdown），可点段落编辑 | 「建议修订」列表 |
| 3 拷问 | 逻辑自洽 | 问题清单为主 | 关联段落高亮 |

原则：

- **默认不露出 JSON**；高级用户可「源数据」折叠打开  
- AI 产出必须是「可采纳卡片」，不是长聊天记录墙  
- 阶段切换（设计→架构→测试）用顶部 **进度条**，未解锁阶段不可点进空壳页  

### 3.3 架构 / 测试阶段（以后）

- 架构：在同一需求下新增「技术方案」「SR 列表」视图  
- 测试：SR → 测试方案 / 用例建议  
- 进入这些阶段前，必须已绑定工程目录  

## 4. 关键交互原则（建议拍板）

1. **工程上下文永远可见**（顶栏显示工程名与路径）  
2. **一次只强调一个主行动**（例如「回答下一问」或「采纳 3 条修订」）  
3. **聊天不是首页**：对话是手段，文档与问题清单才是结果  
4. **中文优先**，专有词保留 PRD / SR  
5. **失败可理解**：Claude 未配置、工程无 `.claude`、权限被拒，都要用人话说明
