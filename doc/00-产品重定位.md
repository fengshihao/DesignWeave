# DesignWeave 产品重定位

> 状态：已拍板 · 2026-08-15  
> 目的：安装程序把本机跑成服务器；浏览器进工作台；架构师 / 产品设计靠账号和 ACL 区分。文档有专有目录，代码仓默认只读。

## 1. 产品是什么

一句话：**给产品 / 设计 / 测试用的 Cursor / Claude Code。**

人看和改的是 Markdown 交付物（墨览），机器干的是 Claude Code 那套：读仓库、搜代码、改文档、追问缺口。人不用面对终端、源码树、prompt、MCP。

```text
想法 / 口述 / 粘贴草稿
        ↓ 共创、细化、拷问
      PRD.md（墨览里改）
        ↓ 只读看代码仓
      可行性 + 技术方案
        ↓ 拆任务
      SR / 任务清单
        ↓
      测试方案与用例
```

墨览不是产品本身，是人机共用的纸面。VS Code 墨览扩展继续服务「已经在 IDE 里的人」，不当主产品。

## 2. 两个角色（已拍板）

**同一套 Web，权限不同。** 不上 Tauri 工作台。

| 角色 | 入口 | 能做什么 | 不能做什么 |
|------|------|----------|------------|
| **架构师** | 浏览器（登录为架构师） | 配 Claude / MCP / skills、浏览服务器目录挂文档根和代码根、管账号、写文档、开 Agent | — |
| **产品设计** | 同一套浏览器 | 在已有工程里编辑 Markdown、开 session、看 Agent 进度 | 改配置、看密钥、增删代码根 / MCP、管用户 |

MCP / skills：**默认全开**（复用托管机 `~/.claude`）。架构师可在设置里关掉；产品设计看不到设置。

安装完成后第一个账号就是架构师。产品设计由架构师创建，只拿地址和登录方式。

## 3. 纠正后的产品假设

| 原假设 | 现假设 |
|--------|--------|
| Docker / 云 / Tauri 桌面壳 | **安装程序 + 以服务器方式运行的本机程序** |
| 角色靠不同客户端区分 | **用户系统 + ACL**；界面都是浏览器 |
| 文档写进主仓 `.designweave/` | **每个工程一个专有文档目录**；代码仓全部默认只读 |
| Agent 自带一套工具 | **复用托管机上的 Claude Code**；默认全开，架构师可关 |

## 4. 运行形态（已拍板）

```text
托管机（安装包打进去）
├── 本机服务器进程（开机可启动）
│     Web UI + API + Agent 调度
│     内置 Node
├── 用户 / ACL（架构师、产品设计）
└── 磁盘：文档根（可写）+ 代码根 × N（只读）

架构师 / 产品设计 ──浏览器──▶ http://主机:端口
```

- 需要 **安装程序**（先 macOS，再 Windows）：装完即服务，不必 `pnpm dev`。  
- **不做 Electron / Tauri 工作台。** 不为「原生窗口」单独做一层壳。托盘启停若以后要，是安装器的小事，不是产品主界面。  
- **不换 Deno/Bun。**  
- 服务可听本机或局域网；**必须登录**；不对公网裸奔。  
- 选目录：服务器端文件树（浏览托管机磁盘），不是访问者自己电脑的系统文件夹框。  
- Docker 只留开发者附录。

### 4.1 由此带来的产品含义

| 点 | 含义 |
|----|------|
| Claude / MCP | 只存在于 **托管机**；全员用架构师配好的能力包 |
| 选文件夹 | 架构师在网页里浏览 **服务器本机路径** |
| 长任务 | 活在后台 `session_id` 里；关浏览器不等于取消 |
| 写代码 | 默认关。Agent 只改文档根 |
| 权限 | 同一 API，按角色拒绝；不是靠「换一个客户端」 |

## 5. 与 Claude Code 的关系

DesignWeave **不是**另起一套 Agent 生态，而是：

> 在文档工作流之上，**调用托管机上已配置好的 Claude Code（Agent SDK）**。

服务启动时扫描并复用 `~/.claude/settings.json`、`~/.claude.json`、工程 `.claude/`、MCP / plugins。**默认全开**，密钥只引用、不复制。只有架构师能改开关。细节见 [01](./01-Claude配置复用与工程绑定.md)。

## 6. 工程怎么绑

一个工程 = **1 个文档根（可写）** + **0～N 个代码根（只读）**。

未绑代码仓允许：只有文档根，可行性分析不可用。见 [06](./06-OEM产品经理场景与实现决策.md)、[07-客户端架构.md](./07-客户端架构.md)。

## 7. 明确不做（本阶段）

- Docker Compose 作为主安装路径  
- Tauri / Electron 当工作台或「架构师专用壳」  
- 产品设计改 MCP / 密钥（靠 ACL，不是靠藏接口）  
- 默认改业务代码  
- 多租户公网 SaaS  
- 绕过企业 Claude Code、另建平行 MCP 市场  
- 通用笔记库（wikilink / 图谱 / 日更）
