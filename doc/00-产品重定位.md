# DesignWeave 产品重定位（草案）

> 状态：讨论中 · 2026-08-09  
> 目的：纠正 MVP 假设，明确「本地单用户安装 + 绑定现有工程 + Claude Code 配置复用」。

## 1. 纠正后的产品假设

| 原 MVP 假设 | 纠正后 |
|-------------|--------|
| Docker / 云部署 | **装在一台内网机器上当小服务器**（Win / Mac / Ubuntu），**不做 Docker 主路径** |
| 本机单用户 Tauri | **多人用浏览器访问同一台机器**（局域网） |
| 项目从空白想法开始 | **多数需求挂在服务器本机已有工程目录上** |
| Agent 自带一套工具 | **复用该服务器上的 Claude Code settings / skills / MCP** |
| 双栏 UI 定稿 | UX 需重做，当前实现仅作技术探针 |

## 2. 运行形态（已拍板场景）

**主场景：一台机器当小服务器，多人浏览器用。**

```text
内网机器（安装 DesignWeave）
├── 安装包 / 解压包（无 Docker）
├── Node runtime（内置或预装）
├── Agent + Web 服务监听 0.0.0.0（或内网网卡）
├── 本机 Claude Code 配置（全员共用这一套）
└── 本机工程目录（需求绑定这些路径）

同事 A/B/C ──浏览器──▶ http://服务器IP:端口
```

### 打包方向（按此场景重排）

1. **首选：服务型安装包**（不是 Tauri 主路径）  
   - 安装后注册为系统服务或「开机可启动的后台进程」  
   - 提供开始菜单 / `.desktop`：启动、停止、打开管理页  
   - 平台：Windows 服务或托盘启动器；macOS `launchd`；Ubuntu `systemd` 用户/系统单元  
2. **可选薄壳**：极简托盘程序（可用 Tauri）仅负责启停服务，**不是**每人装一份客户端  
3. **不做**：每人装 Tauri 再点对点协作；不做公网暴露

**Tauri 在此场景的定位：** 可选的「服务器托盘/启停器」，**不是**多人访问的必要组件。优势主要是运维方便，不解决多浏览器访问本身。

### 2.1 局域网访问（主路径）

- 服务默认监听 **`0.0.0.0`**（或可配置绑定网卡）  
- **必须鉴权**（至少共享口令；后续可简单账号）  
- 建议仅内网；文档明确「不要对公网开放」  
- 可选内网 HTTPS / 反代（Nginx/Caddy），第一版可用 HTTP + 口令  

### 2.2 由此带来的产品含义

| 点 | 含义 |
|----|------|
| Claude 配置 | 复用的是 **服务器机器** 上的 Claude Code，不是每位同事笔记本上的 |
| 工程目录 | 路径是服务器本地盘（或该机挂载的网盘）；浏览器端是「选服务器上的目录」 |
| 并发 | 多人同时开需求/跑 Agent，要考虑会话隔离与队列（后期） |
| 权限 | 能登录的人 ≈ 能驱动该机 Claude/MCP；口令要当机密管 |

## 3. 与 Claude Code 的关系

DesignWeave **不是**另起一套 Agent 生态，而是：

> 在设计师/架构师/测试的文档工作流之上，**调用本机已配置好的 Claude Code（Agent SDK）能力**。

安装或首次启动时应扫描并复用：

| 来源 | 典型路径 | 用途 |
|------|----------|------|
| 用户 settings | `~/.claude/settings.json` | 语言、模型路由、环境变量引用方式 |
| 全局状态 | `~/.claude.json` | 已知工程列表、使用习惯（只读参考） |
| 工程级配置 | `<repo>/.claude/` | skills、项目指令 |
| MCP / plugins | Claude Code 与 marketplace 配置 | 企业内工具链 |

原则：

- **优先引用，不复制密钥**到 DesignWeave 数据目录。
- 敏感字段（token 等）永不写入 DesignWeave 导出文档或日志。
- 若扫描失败，引导用户确认 Claude Code 已安装并可在终端运行。

## 4. 「需求」与「工程」绑定

创建需求（PRD 工作项）时必须：

1. 选择或浏览 **本地已有工程目录**（可从 Claude 已知 projects 列表预填）
2. 将该目录作为后续 Agent `cwd` / 可行性分析 / 代码核对的根
3. DesignWeave 自己的文档资产可放在：
   - `\<repo\>/.designweave/`（推荐，跟仓走），或
   - 用户选择的中央工作区（少用）

## 5. 明确不做（本阶段）

- Docker Compose 作为主安装路径
- 多租户 / 云端协作
- 绕过企业 Claude Code 配置、另建平行 MCP 市场
